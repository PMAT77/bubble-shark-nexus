## [0.19.0] - 2026-10-11

同模式升级保留现有 `panel.env`、实例、存档与备份；Docker 与 Native 之间不自动迁移。

### Fixed

- 修复“重置世界”仅重新加载最近存档的问题；整房间与指定种子生成均支持运行或全部停止状态，并在生成后核验实际会话与种子。
- 修复种子持续显示正在生成及地上、洞穴不同种子无法共享 Mod 加载入口的问题；读取结果不会覆盖草稿。
- 按当前世界会话中的编号文件读取游戏快照，显示实际游戏天数、保存时间和洞穴对应快照；整房间回档锁定明确编号，不再使用“回档几天”或保存时间补偿。
- 安全备份失败暂停维护操作，原操作人可再次确认不备份继续；保存等待各分片完成回调及落盘证据，归档遇到并发保存最多重试一次。

- 修复权限或菜单初始化失败后反复跳转登录页、首屏持续显示加载动画的问题；加载失败或超过 30 秒时显示原因与重新加载入口，网络失败保留登录会话。
- 修复首屏星空动画结束后仍持续绘制的问题；保留星空效果，限制帧率与画布分辨率，并在页面隐藏时暂停。
- 修复缺失的脚本和样式返回页面内容的问题，缺失静态资源返回 404。

### Changed

- 移除世界维护回档区的房间配置保留数量说明与空存档点提示。
- 世界种子共用一个输入框，自动填入已读取的当前种子，停服后保留；右侧按钮统一为“重置世界”，未修改沿用原种子，留空随机，修改后按新种子重置。读取、保存其他配置或普通重启不会应用或覆盖已生成世界的种子草稿。
- 移除实例控制中的资源与启动设置区域、相关入口及详情与控制台的启动明细卡片；新启动统一使用服务器 `panel.env` 的内存限额与等待时间，历史实例覆盖停用，正在运行和启动中的任务保持本轮配置。
- 确认启动时内存与 swap 余量不足后，在右上角提示并提供创建或追加 swapfile 命令的一键复制；同一启动任务只提醒一次，未知指标与历史失败记录不触发提示。
- 世界维护集中到实例详情与控制台的快捷指令，提供保存存档、自定义回档与重置整个房间；各按钮独立显示操作状态，后台任务支持刷新页面及面板重启后核验。
- 世界生成和回档按现有权限分别鉴权，维护账号无需控制台读取或额外生命周期权限；世界重置清除旧游戏快照，历史恢复依赖另行保留的面板备份。
- 生产静态资源默认支持 gzip 与 Brotli 压缩，Naive UI 组件改为按需加载，减少首次访问的资源传输量。

## [0.18.0] - 2026-10-10

### Added

- 实例控制新增资源与启动设置，可分别调整主世界、洞穴内存硬限与每片等待时间；支持继承全局配置、应用基于 Mod 估算和实测峰值的推荐值。
- 实例启动显示排队、分片加载、洞穴互联与就绪阶段，以及耗时、剩余预算和资源诊断；保存最近启动报告，面板重启后恢复监控并保留原始期限。
- 新增游戏共享物理内存预算与 root 命令 `bsp setup-memory-budget`；资源设置显示整面板占用、宿主预留、实际共享预算及保护是否生效。
- 加载与运行期间持续采集内存压力；确认本轮 OOM 或持续严重回收时保护停止整个实例，保存现场并发布异常通知；计划任务、插件与面板恢复不会自动解除保护。

### Fixed

- 修复 Native 模式自动内存软限导致主世界加载停滞、启动超时的问题，保留配置的内存硬限、swap 与 CPU 配额。
- 修复运行时探测失败被误判为分片退出，以及停止或重启后旧启动等待任务继续运行的问题；启动失败时关闭日志跟随，故障诊断区分实际内存硬限与尚未验证的配置上限；停止操作会清理数据库已标为停止的残留洞穴；Native 同名单元的创建与清理串行执行，旧停止任务不会删除新轮服务文件。
- 修复低分片硬限截断启动预算、保留余量未生效及无法通过 `BSP_HOST_MIN_AVAILABLE_MB=0` 关闭守卫的问题，区分 swap 未配置、余量不足与已用满。
- 修复 swap 创建回退为固定 2 GiB 的问题；显式新路径可追加 swapfile，已有 active 目标保持幂等，禁止覆盖现有文件。
- 修复首装忽略显式 `BSP_SWAP_SIZE` 的问题，安装摘要与实际创建容量保持一致。
- 修复运行期 OOM 后普通对账抢先清除主世界引用、遗留洞穴的问题，保护停机优先处理两片；Docker 缺少宿主指标挂载或面板身份时保持未知。

### Changed

- 启动等待与状态检查复用未变化的分片日志解析结果，减少重复读取和扫描。
- 新安装 small、medium 预设的 DST 每片硬限分别调整为 3072、4096 MiB；无现有 swap 时首装按 MemTotal 创建 4、3 或 2 GiB 共享 swap。已有配置、active swap 和运行实例保留，旧部署保护缺失时显示告警。新默认值的 Native/Docker、4G/6G RAM 与不同 swap 容量组合实测尚待验证。
- 推荐值纳入同次 RAM＋swap 占用，受硬限截断的峰值标为需求下界；完整就绪时冻结启动采样峰值，运行后的内核峰值单独显示。
- 单世界与双世界统一后台启动，同节点任务排队，默认每片等待 300 秒；就绪由本轮游戏内查询确认，游戏进入错误界面时不判为就绪，双世界还需确认洞穴互联。
- 启动请求受理后提示正在启动，完整就绪后提示成功；加载静默时展示诊断，明确的 OOM、Lua 错误或进程退出立即反馈。

## [0.17.0] - 2026-10-10

### Changed

- Mod 配置展示默认值，内部配置键移入说明提示；保留未修改值的类型及未展示的已有配置，手动填写时检查空键与重复键。

- 修复 Mod 配置弹窗输入框与删除按钮越界，适配窄屏及多行配置；支持读取变量、函数和循环生成的配置选项，并区分无配置与读取失败。
- 修复部分创意工坊 Mod 压缩包因内部路径使用反斜杠而无法安装的问题，保留路径安全与文件校验。
- 下载失败的 Mod 同时提供重试与取消订阅入口，覆盖已订阅列表、创意工坊列表及详情页的桌面与移动端界面。
- 修复空闲或暂停队列中的待下载 Mod 被误判为正在下载、导致单项下载入口不可用的问题。
- 未就绪的 Mod 显示“未就绪，无法启用”，避免下载失败或待下载时因保留启用设置而显示已开启；就绪后恢复原设置。

## [0.14.0] - 2026-10-04

### Added

- Mod 页面支持一个 ZIP 导入多个 Mod，提供逐项预览与统一覆盖确认；新增项默认禁用，覆盖保留启用状态、顺序和配置。安装失败恢复该项旧内容，保留成功项并仅重试未完成项；本地内容不使用旧 Steam 清单判断版本。
- 迁移包可选包含 Mod 文件，面板与独立导出脚本共用版本化清单及 SHA-256 内容校验；通过现有存档导入入口离线恢复完整 Mod 列表，缺文件项保留为待下载。

### Changed

- Mod 市场移除连接失败提示与重复的重试按钮，无数据时显示「暂无 Mod 数据」，统一通过「刷新列表」重试。
- 监控页内存卡片移除「可用缓冲」文案。
- Mod 下载统一展示等待任务、下载、重试与暂停状态；导入存档后可直接进入当前实例的已订阅列表，禁用的缺失 Mod 可单独下载，本地列表不等待 Steam 元数据。
- Mod 市场与详情支持持久缓存及离线回退，限制请求与补全的总等待时间；新增按需查看的脱敏访问记录和代理配置引导。
- Mod 下载详情并入状态条，结束后移除过期操作提示；故障帮助优先展示失败原因与恢复步骤，技术记录和管理员配置默认折叠，移除重复的本地导入按钮。

- 本地与 CI 共用质量门禁，消除重复后端单测与类型检查，安装器跳过状态明确显示；精简锁定代码写法的测试并保留权限、安装升级和数据完整性检查。

- 「检查更新」增加下拉菜单，勾选并停止实例后可「强制更新所选实例」，保留存档和配置；移除列表与详情中独立的「校验并更新游戏文件」入口。
- 「更多」菜单中的更新操作简化为「更新」，检查进度提示改为「正在检查更新…」，安装日志来源标签简化为「SteamCMD」。
- 监控页内存信息精简缓存区提示，商业支持页精简报价说明与赞助备注。

### Fixed

- 质量门禁失败时保留单测失败用例及诊断信息，避免日志末尾的通过用例掩盖报错。
- 修正插件生命周期回归测试，避免正常完成状态导致发布门禁间歇性失败。
- Mod 显式下载与更新意图在暂停、取消和面板重启后保留；批内部分失败按单项证据验收，强制更新不会把旧文件当作本次成功。显式订阅统一使用实例队列轮询。

- 本地 Mod 导入支持逐项恢复文件、配置和数据库，新版迁移恢复支持世界、Mod、配置和数据库整体回滚，并在面板重启后恢复中断事务；加强 ZIP/tar.gz 路径、链接、重复条目、CRC 和资源限额校验，迁移包重下载校验实例归属。

- 系统管理员角色改为内置只读，禁止修改名称、备注、权限点或删除；启动时自动修正已有角色及成员权限，管理员继续拥有全部操作权限。
- 检查更新同时核对 Steam 正式分支的内容清单、已安装 depot 和安装状态，发现 Build ID 相同但内容版本不一致或游戏文件缺失时提示更新；信息不足时显示无法判断，避免旧版改写安装编号造成误报。

## [0.13.3] - 2026-10-01

### Fixed

- **因内存不足启动失败时会说清原因并给出扩容引导**：此前只能看到「反复重启」，真凶（分片被 cgroup 按内存上限杀掉）得登录服务器翻 `dmesg` 才看得见，因为 systemd 的退出原因会在重启成功后重置、面板又读不到内核日志。现在优先读该分片的 cgroup OOM 计数（进程被自动拉起后仍然保留）与内存峰值，判定为内存原因时在实例上写明「被系统按内存上限终止过 N 次（上限 M MiB，实际峰值约 X MiB）」，并给出「增加缓存区」的引导对话框：先在面板停止实例、再执行命令、然后重新启动，命令可一键复制。不是内存原因的未就绪（例如某个 Mod 报错）走另一套措辞，指向控制台日志，不会误导去加缓存区。
- **实例早已恢复正常，「反复重启」的警告却一直挂着**：判据是 systemd 的累计重启次数，只要崩过一次就永远大于 0（只有面板主动启动时的 `reset-failed` 才会归零），而清除警告的条件又要求它为 0——事实上永远不成立。于是「启动阶段崩过一次、之后连续跑了半小时」和「正在崩溃循环」在界面上长得一模一样，服主会照着提示去减 Mod、关洞穴，白折腾一轮。现在按**当前进程已连续运行多久**区分：运行时正在自动拉起、或当前进程跑了不到 10 分钟，才说「实例进程反复重启」；已经站稳则改说「实例在启动阶段崩溃过 N 次，当前进程已恢复运行，若大厅仍搜不到房间请查看控制台日志」，连续干净运行满 30 分钟后警告自行消失。
- **实例卡片的「运行时长」会把重启盖过去**：它算的是面板点启动的时刻，而进程被 systemd / 容器运行时自动拉起后那个时刻不会更新，于是出现过「运行时长 16 分 55 秒 + 已重启 1 次」这种看起来一切正常的读数。现在优先取运行时给出的进程运行时长（Native 用 systemd 的 monotonic 启动时刻与系统 uptime 相减，不受本地时区缩写影响；Docker 用容器的 `StartedAt`），运行时给不出时才退回旧口径。
- **「缓存区用满」被说成「未配置缓存区」**：判据原先只看 `SwapFree`，它为 0 时一律按「没有 swap」处理并让人执行 `gsh setup-swap`——而脚本检测到已有 swap 会直接返回、什么都不做，照着做一遍没有任何变化，排查方向被带偏。现在按 `SwapTotal` 与 `SwapFree` 组合区分：确实没配置才提示 `gsh setup-swap`；配置了但已被用满则明说「缓存区已用满（共 N MiB），加载尖峰没有落点」，并给出扩容到 4 GiB 的完整命令（先停用并删掉旧 swapfile，再以 `GSH_SWAP_SIZE=4G` 重建）。退出原因、启动守卫提示与内存不足通知三处口径一致。

- **`pnpm run test:unit` 会莫名多出一个失败**：测试运行器带 `--test-force-exit`，它在测试跑完后强制结束进程，而这时插件子进程与套接字可能仍在关闭过程中；Windows 上 libuv 会因此在 `src/win/async.c` 断言失败，表现是**某个文件级用例被判失败且没有任何断言信息**（`fail 1`，测试总数比实际多一项）。去掉这个开关，让测试进程自己干净退出（全套约 2 分钟跑完）。将来若有用例真的不退，那是句柄泄漏，应当去修它。
- 面板退出时不再把插件子进程丢在原地：`shutdown` 会等它们真正退出，宽限期内没退的就强杀；退出过程中到达的进程退出通知也不会再安排新的重启退避（此前会在数据库已关闭后触发一次读库并抛错）。

## [0.10.0] - 2026-09-29

### Added

- **成员与角色：多个账号各管一摊**。侧边栏里「成员管理」与「角色管理」是两个独立的一级菜单（排在「商业支持与 Pro」之前）：管理员在「角色管理」里建角色、勾选权限点（53 个，覆盖实例启停、改房间配置、踢人与封禁、Mod、文件、备份恢复、计划任务、面板设置等），在「成员管理」里建子账号、分配角色并勾选它能看到哪些实例。**角色决定能做什么，实例授权决定能在哪些实例上做**，两者同时满足才生效。子账号登录后侧边栏只出现它有权进入的模块，直接输地址也进不去（无权页面的路由根本不会注册）；未被授权的实例，在实例列表、状态计数、监控、备份与计划任务里都不会出现。建子账号默认要求首次登录改密。
  > 典型用法：给帮忙管秩序的朋友建一个「能踢人、不能封禁」的角色；给托管同事建一个「只能改房间配置、不能启停实例」的角色。
- **升级自动迁移**：从旧版本升级后，原管理员账号会自动获得「系统管理员」角色（全部权限）与现有全部实例的授权，不需要手工修数据；其他已有账号按其原有权限映射成对应角色，不丢能力。
- **内置「游客」角色现在真的能用了：能看除成员、角色管理外的所有页面，但一个操作也做不了**。此前这个角色被固化成"零权限"，挂上它的账号登录后侧边栏空空如也，只有首页那句「当前账号还没有被分配任何模块权限」。现在它固定持有**除「成员管理」「角色管理」外的全部只读权限点**（监控台、实例管理、实例详情与控制台、房间、世界、玩家、Mod、备份、计划任务、插件、商业支持与 Pro、系统设置），而服务端对**所有写接口一律拒绝**——判断放在 `resolveAuthorizedContext`，全局与实例两级接口都覆盖，即便有人绕过角色管理接口直接改库给游客加上写权限点也不生效。
  > 用法：在「成员管理」里把成员的角色选成「游客」，再勾上它可见的实例——**角色决定能做什么，实例授权决定能在哪些实例上做**，不勾实例时页面能打开但列表是空的。权限点是代码固化的（`shared/constants/permissions.ts` 的 `GUEST_ROLE_PERMISSIONS`），面板每次启动都会同步一次，所以升级后的老部署也会跟上；角色管理页不能改它、也不能删它。
- 环境自检与操作记录不受影响；操作记录里每条写操作都带上了操作人账号，「谁在什么时候重启了世界」现在查得到且**能区分是哪个账号做的**。
- **游客角色登录后会明确告诉你「当前是游客模式」**：面板右上角常驻一条提示——「这个账号只能查看，不能做任何操作——所有操作入口都已隐藏。」它**不会自动消失**，点「知道了」或右上角关闭才收起。这条提示补的是游客账号进来看到"到处都是灰的、没有按钮"时的困惑：那些入口本来就是按权限隐藏的，不是页面坏了。同一个账号关过一次就不再弹，换个账号登录会重新提示（判定用的是服务端返回的角色种类，不是"权限点全是只读"的猜测——管理员自建的只读角色不会被误报成游客）。
- **游客登录（只读预览入口，默认关闭）**：在 `panel.env` 设置 `GSH_GUEST_LOGIN_ENABLED=1` 后，登录页的登录按钮下方会出现一个「以游客身份预览」按钮，**点一下即进入只读预览**，不需要任何账号密码。面板启动时会自动预置这个只读账号，它的口令是一个当场生成、随即丢弃的随机值——不返回、不落盘、不出现在日志里，所以它**只能**通过这个按钮进入，用普通登录页反而登不上（这是刻意的：任何写进前端的口令都会变成公开静态资源的一部分，拿到它就能绕开按钮反复登录）。游客账号名可用 `GSH_GUEST_LOGIN_ACCOUNT` 修改（默认 `guest`）。**为什么默认关闭、而且默认在 Docker 模式下打不开**：Docker 模式的面板挂着 `docker.sock`，一次有效登录等价于宿主机 root，把只读账号开给外面的人等于把宿主机交出去——所以这个开关只在 **Native 模式 + production** 下真正生效，Docker 部署即使设成 1 也不会开放，并会在启动日志里说明原因。开启后请在反向代理层再加一层访问控制（IP 白名单 / Basic Auth / VPN）。
  > **开启前请看 [SECURITY.md](SECURITY.md) 的「游客角色（只读预览）的硬前提」**：只读不等于看不到东西——实例目录与文件内容、房间与世界配置、玩家名单（含管理员名单）、在线玩家、备份列表与游戏控制台日志都对访客可见，不要在有真实玩家数据的机器上开放。另外建议把 `ADMIN_USERNAME` 从默认的 `superadmin` 改掉。
- **游客能看到的东西比上一版更窄了，而且"只读"变得更硬**：游客角色的权限集现在排除**操作记录**（`audit:read`）与**插件**（`plugin:read`）——前者的每一条都是「管理员账号名 + 改了哪个实例的什么」，后者会回面板数据目录的绝对路径，公开预览时它们是最容易被拿去撞库与做资产测绘的信息；同时排除**控制台读**（`instance.console:read`），因为「实例详情」页会借它调用 `/app/instance/world-state`，而那个接口实际会**向运行中的游戏下发一条 `print` 指令**。这类"方法名是读、实际会改状态"的接口现在被统一拦住：判据从"是不是写权限点"改成 `isStateChangingPermission`（写权限点 **或** 标了 `sideEffect` 的读接口），游客连"绕过角色管理接口直接改库给自己加权限"都不生效。
- **游客角色不会再被误配到运维账号上**：内置游客角色只能分配给配置里的那个游客账号，在建号与换角色两条路径上都会被拒绝。挂到在用的运维账号上会让那个账号**静默失去全部操作能力**——还用自己的密码登录，但所有按钮消失、写操作一律返回「当前账号是只读的游客角色」，而界面上不会说明原因；历史上已经配错的账号会在启动日志里被点名。同一个游客账号的口令也不允许在「成员管理」里重置：一旦它有了已知口令，免密入口上的开关与限流就都可以绕过。
- **主机信息不再向游客暴露指纹**：`/app/system/info` 对游客身份不再返回 `hostname`、内核版本与 CPU 型号，CPU/内存/磁盘/网络的数值照常返回。主机指纹对"看演示"没有价值，对"找目标"很有用。
- **同一账号的实时日志流有了并发上限**：控制台的 SSE 流此前只限制"票据"数量，而票据是一次性的、账号可以反复签票，所以一个已登录账号能挂起任意多条长连接（每条在服务端留一个订阅回调与一个 15 秒心跳）。现在每个账号最多 4 条，超限回 429 并提示关闭其它控制台页面。
- **登录会话表不再只增不减**：`auth_sessions` 此前没有任何回收机制，每登录一次就多一行、行里带着 user_agent 与来源 IP。现在面板启动时会清理已经不可能再生效的记录（刷新令牌已过期、或早已被吊销）。

### Changed

- **角色权限不再是一堵「复选框墙」**：新建/编辑角色此前把 53 个权限点按 13 个模块全部平铺出来，每组一行两三个复选框——扫不完，也看不懂「分配端口」「编辑玩家备注」到底能干什么（`PermissionSpec.summary` 写了那句话，却从没在界面上出现过）。现在改成抽屉里的四层结构：**先选起点**（只读看板 / 日常运维 / 完全管理，分别复用权限点真源里的游客基线、一份保守的运维清单与全量清单）→ **13 个模块默认折叠**（组头显示「已选 3/5」）→ 展开后**纵向单列**排列表项 → **顶部搜索**（按名称与用途匹配，支持「踢 玩家」这样的多词）。每一项都带上那句说明，会弄坏东西或能把权限发出去的 12 个权限点标「高风险」。另加两条护栏：勾了操作权限却一个「查看」权限都没勾时给出警告并可一键补齐（服务端菜单是按 `read` 权限点过滤的，这种组合下成员**根本进不去那个页面**，权限等于没给）；保存一个没有任何权限的角色前先确认一次。权限点的数据格式没变，服务端与已有角色都不受影响。
- **成员管理与角色管理改成与其它列表页同一套排版**：这两页此前把表格包在一张 `NCard` 里、操作按钮挂在卡片右上角，而计划任务等页面是标题、按钮行、表格依次平铺——同样是列表页，看起来却像两种版式。现在两页都去掉外层卡片，按钮移到标题下方，表格直接铺在页面里：加载态交给表格自己的 `:loading`（不再用 `v-if` + `NSpin` 整块切换，加载时表格骨架不再闪没）、`pagination` 明确关掉，空态通过表格的 `#empty` 渲染；操作列按钮由 `quaternary` 改为与计划任务一致的 `secondary`，窄屏下同样按 `scroll-x` 横向滚动。

### Fixed

- **菜单能进、页面里的请求却必然被拒**：这类错位此前散在七个模块里——「房间管理」「世界管理」「玩家管理」「模组管理」「备份与恢复」「计划任务」的列表数据来自实例列表，只勾了模块自己的查看权限时菜单照样出现，点进去却是一张 403 的空表；「成员管理」要拉角色与实例列表才能分配角色与实例授权，缺了同样建不出可用的成员；「实例详情」对只有「查看实例」的账号会一次并发六七个无权请求，失败被吞掉后卡片显示"—"，看起来像"这里没有数据"。现在**每个页面只请求自己那份数据**：房间/世界/玩家三个列表页各有自己的投影接口（各自只要求 `room:read` / `world:read` / `player:read`，且只返回这一页要用的字段），"要在界面上选一个实例"的模块（Mod、备份、计划任务、成员授权、玩家详情）走只回实例标识的选项接口，成员管理的角色下拉也只取角色名；实例详情页按权限决定发不发请求，文件、迁移报告、指令中心三块改为无权时显示"当前账号没有 XX 权限"，而不是挂在那里报错。**可见范围仍然只由实例授权决定**：没被授权的实例在列表、计数、下拉里都不出现。
  > 一处刻意的收紧：这些页面现在能列出**被授权实例**的名称与状态（此前只有「查看实例」的账号能列），但安装路径、端口与账号未获授权的模块字段一律不返回。<br>另外**取消「查看实例」只影响「实例管理」这一个菜单**——上一版曾让它连带收走房间/世界/玩家/Mod/备份/计划任务/成员管理，那是把"页面需要数据"错当成"角色必须持有那个权限"，已改掉。
- **只勾「查看操作记录」的账号进得去系统设置，却看不到操作记录**：菜单对「系统设置」是任一语义（`settings:read` 或 `audit:read`），但这三个 tab 此前无条件渲染，而页面挂载时无条件请求 `settings:read` 的两个接口——请求失败后整页显示"无法加载系统设置"，把自己有权看的那一屏也挡住了。现在页内 tab 按权限过滤（面板设置 / 通知渠道要 `settings:read`，操作记录要 `audit:read`），没有权限的接口一个都不请求，加载失败也只在面板设置那一屏里提示；`?tab=` 指向自己无权的 tab 时回落到第一个可见 tab，而不是落到空页。
- **「监控台」对只看监控的账号是坏的**：这一页的数据来自 `/app/system/info` 与 `/app/system/network/realtime`，两个接口此前都要求「查看面板设置」，于是只勾「监控台」权限的账号进来只能看到"系统信息加载失败"。现在这两个只读接口接受「监控台」或「查看面板设置」任一权限（写操作仍只认 `settings:write`）。同一类问题一并修掉：实例管理页读运行环境需要的 `/app/system/steamcmd/config` 与节点列表 `/app/node/list` 分别接受「查看实例」，**只有「创建实例」权限的账号不再因为"运行环境未就绪"而建不了实例**；系统设置页读写目录的「浏览」按钮、以及各页面里指向别的模块的跳转按钮（房间设置 ↔ 世界设置 ↔ 玩家管理等），无权时不再出现——那些跳转是按路由名进行的，目标路由无权时根本不存在，点下去只会在路由解析阶段抛错。
- **管理员刚改完权限、成员没刷新页面时，菜单和页面还是旧的**：菜单与"我能进哪些页面"是登录时的一次快照，而服务端每次请求都查库，于是出现"菜单还在、点什么都 403"。现在收到 403 时会重新拉一次权限，**只有权限确实变了**才提示「权限已变更」并自动重新加载（权限没变的 403 属于这个功能本身无权，不会白闪页面，也不会成环）。

- **超级管理员账号不会再被别人重置密码或停用**：成员管理里，配置的管理员账号（默认 `superadmin`）不再出现「重置密码」，也不再出现「停用」（这行账号后面带「超级管理员」标签，悬停会说明原因）；接口本身同样拒绝——重置密码连管理员给自己重置也不行，停用则一律拒绝（保留「启用」，历史数据里若是停用状态还能恢复）。这两条入口开着的时候，「谁是超级管理员」实际取决于谁先点了那个按钮：账号一旦被盗，攻击者第一件事就是给别人重置密码、或者反过来把真正的管理员停掉。现在这个账号的密码只能由本人在**个人设置 → 修改密码**里改（要验旧密码），登录页的「忘记密码」不受影响。忘了密码也不是死路：服务器上可以跑 `reset-admin-password` 脚本，或用 `ADMIN_PASSWORD` 配合 `GSH_SYNC_ADMIN_PASSWORD_FROM_ENV` 同步——这两条都要求能登录服务器本身。
- **计划任务可以改到别人的实例上**：修改、删除、立即执行三个接口原先只凭任务 ID 就执行，不校验这个任务属于哪个实例——任何持有运维权限的账号都能改、删、立刻触发**任意实例**的定时重启与备份。现在按任务自身的实例归属校验。
- **批量操作会波及没授权给你的实例**：实例指标与「检查更新」在不传实例列表时，原先作用于本机**全部**运行中实例。现在缺省范围是「全部**可见**实例」，并且指定了未授权实例时整体拒绝，不做部分执行。
- **菜单接口对匿名请求开放**：`GET /app/route/list` 原先既不校验登录、也不按权限过滤，等于把整张功能地图（含每一项需要的权限点）交给匿名请求，而且让无权页面照样能被直接输地址访问。现在要求登录，并只返回该账号有权进入的部分。

- **地形图里未收录地块的着色不再与周围地形打架**：游戏版本新增地块、面板还没收录它的名字与配色时，图上的颜色是按地块 ID 散色相派生出来的——真机上那三个未收录地块（#263 / #269 / #272）面积都很小、混在成片海洋里，于是海面中间冒出三块与蓝色毫无关系的高饱和色，看起来像渲染坏了。现在**落在已知 ID 段内的未收录地块以该段已收录地块的基调色相为基准**，只在基调附近做小幅偏移：既与周围地形同一色系，同类里的两三块又仍然分得开。段位按色板里的真实色系划分：**200–256 海洋蓝、257–260 沙滩黄、261–288 海洋蓝（浮冰所在的新增段）**——中间这两截必须分开，因为色板里 257（猴岛沙滩）是黄的、264（浮冰）是蓝的，合成一个"岸线"段会把两者之一涂错色。其余 ID 段（陆地）保持原样按 ID 派生——陆地 ID 密集且色相跨度极大，套一个基调色反而更误导。「未收录」这件事照旧由图例置顶与文字标记来说。
- **首页的「进入面板 / 进入实例管理」按钮点了没反应，只在控制台刷出一串报错**：这个按钮原先固定按路由名跳到「实例管理」，而面板内的路由是**按权限动态注册**的——没有 `instance:read` 的账号根本没有这条路由，`router.push({ name: 'nodeInstance' })` 会在路由解析阶段直接抛 `No match for {"name":"nodeInstance"}`，抛在路由守卫之前，守卫兜不住，于是按钮看起来完全失灵。现在按**这个账号实际能进的页面**跳：有实例管理权限进实例管理，没有就进第一个可访问的模块；一个模块都进不去时明说「当前账号还没有被分配任何模块权限」，而不是跳进 404。关闭主页（`app.home.enable=false`）时那个「进入侧边栏第一个模块」的兜底跳转原先也写死了实例管理，同样会让无权账号掉进 404，一并改成同一判据。房间、世界、玩家、Mod 四个列表页空态里的「前往实例管理」按钮同理——没有 `instance:read` 的账号现在不再看到这个按钮（点了只会报错，而且他本来也无权创建实例）。
- **只读账号会看到一堆点了必然失败的按钮**：界面上的写入口此前只有约一半做了权限判断——面板设置的保存与面板更新、备份的删除与恢复、控制台下发命令与清空日志、文件编辑/上传/删除/下载、Mod 启停与配置、房间与世界配置保存、玩家踢人与封禁、地形图生成、插件启停与导入、通知渠道增删改等等，只读账号都能看到，点了才被告知无权限。现在这些入口按各自的写权限点隐藏（输入框本身保持可见，只是提交不了）；新增门禁 `check:write-entries`，会拦住"调用了写接口却没有做权限判断"的界面文件。
- **只读账号打开系统设置的「通知渠道」一进来就是 403**：这个 tab 的渠道列表与阈值读取原先也要求 `settings:write`，于是只有读权限的账号一打开就被拒。现在读取（渠道列表、阈值设置）只要求 `settings:read`，增删改与「测试发送」仍要求 `settings:write`。

## [0.9.0] - 2026-09-24

### Added

- **面板自己也能走代理访问 Steam 创意工坊**：此前只有 SteamCMD（下载游戏与 Mod 文件）支持代理，面板拉取 Mod 市场列表的请求直连 `api.steampowered.com` 与 `steamcommunity.com`——国内服务器上表现为「不配代理就加载不出列表」，而想配也没处可配。现在新增 `GSH_STEAM_HTTPS_PROXY` / `GSH_STEAM_HTTP_PROXY` / `GSH_STEAM_NO_PROXY`（留空时回退读进程的 `HTTPS_PROXY` / `HTTP_PROXY`），面板全部 Steam 请求都会走它；容器部署时指向宿主机代理要写 `host.docker.internal`（compose 已加 `extra_hosts` 映射），**未设置时行为与之前完全一致**。代理是零依赖实现的（`node:http/https/net` 手写 CONNECT 隧道），只作用于 Steam 请求，不会顺带改变其他出站的走向。
- **`GSH_STEAM_COMMUNITY_BASE_URL`**：把创意工坊页面反代到自己的域名，供 HTML 源使用。至此三条链路（官方 API、中继、页面）都能各自换可达的入口。
- **Mod 市场加载在连不上 Steam 时不再是一片空白**：新增离线兜底窗口 `GSH_STEAM_WORKSHOP_OFFLINE_TTL_MS`（默认 7 天）。Steam 完全不可达时，列表会退回最后一次成功拉取的内容，并在界面上明确标注「离线数据 · 最后更新于 X」——此前超过 30 分钟就只剩空列表，而且请求失败还会把已经显示出来的列表清掉。前端同时不再在降级响应里丢弃本地已有内容。
- **「环境自检」新增「Mod 市场上游」一项**：直接给出当前实际生效的链路顺序、代理是否生效（只显示来源变量与主机，不回显凭据）、哪些源正在熔断、以及最近一次成功拉取的时间；没配代理且从未成功过时，会给出可复制的配置写法。
- **面板数据库快照补齐了「下载 / 删除 / 导入 / 恢复」**：此前这个功能只会往磁盘上写一个 `.sqlite` 文件——列表里连操作列都没有，文件躺在那里没有任何出口。现在每行可以下载到本地、删除，也能把外部拿到的快照（别的机器导出的、或你本地留存的那一份）上传进来；上传只入库，面板先校验它是不是本面板的数据库、是不是来自更新的版本，不合格的直接拒绝。**恢复**在面板内完成：确认框要求手工输入「恢复面板数据」，服务端先给当前库做一份快照、再把替换下来的旧库改名留在原地，然后替换文件并让面板进程退出，由 Docker/systemd 自动拉起（几秒到十几秒，期间页面打不开、当前登录会失效）。启动时会校验恢复后的库，不可用就**自动回退**到恢复前的数据，不会把面板卡成打不开。恢复只回退面板侧数据（账号、实例记录、面板设置），**正在运行的游戏实例不受影响**，磁盘上的实例目录也不会跟着回退。开发环境跑的是 `tsx watch`，恢复后需要手动重启面板。

### Changed

- **Mod 市场列表的等待时间从最坏 75 秒压到 10 秒以内**：此前每个上游源各重试 3 次、每次超时 12 秒，三个源串起来最坏超过 75 秒，而前端 60 秒就放弃了——用户看到的是长时间转圈后列表被清空。现在官方 API 与中继各有 5 秒超时、页面源 12 秒（可用 `GSH_STEAM_WORKSHOP_OFFICIAL_TIMEOUT_MS` / `_RELAY_TIMEOUT_MS` / `_FETCH_TIMEOUT_MS` 调整），**一个源失败后其余源改用 `GSH_STEAM_WORKSHOP_FAST_FAIL_TIMEOUT_MS`（默认 3.5 秒）且只试一次**，整体还有 `GSH_STEAM_WORKSHOP_TOTAL_BUDGET_MS`（默认 10 秒）的总预算，用满即退回缓存/离线数据。
- **上游熔断按源隔离，并且会记住哪个源还活着**：此前任一个源累计失败 6 次就会让所有源一起冷却 30 秒，且后台预热与定时检查的失败也计入其中——用户第一次打开 Mod 市场时常常直接撞上「暂时不可用」。现在每个源各自计数，熔断中的源直接跳过，调度按「最近成功过的源优先」排序；后台任务的失败只记录、不再影响前台请求。
- **Mod 市场列表请求改用独立超时（15 秒）**，与后端 10 秒的预算对齐，不再沿用全局的 60 秒；「重置」按钮不再重复发一次请求（此前会先立即发一次、再被防抖触发一次）。
- 顺带修掉两处会让列表更慢的细节：市场表格补上 `row-key`（翻页不再整表重渲染），移动端卡片里的缩略图补上懒加载。
- **手机上的 Mod 市场列表能看的内容多了一倍**：移动端渲染的是卡片列表，而工具区（搜索框 + 排序 / 时间范围两个下拉）竖排堆叠后要吃掉 300px 以上，卡片的兜底高度却只有 480px，留给列表的不到 200px——只够看一张卡片。现在移动端把卡片下限抬到 640px、列表区最小高度 420px，并压缩了页面内边距、隐藏了移动端冗余的说明段落，实际可用高度多出约 200px（约 2.5 张卡片）。桌面的表格布局不受影响。
- **四类备份入口不再互相混淆**：「备份面板数据」改名「创建面板数据库快照」，并从顶部那一排存档操作里挪进它自己的「面板数据库快照」区块——此前它与「创建存档备份」并排，看起来像第三种存档备份，实际它备份的是面板自身的数据库、一个存档字节都没有。类型标签、计划任务里的同义叫法、空态与确认框文案一并对齐；页面正文只留一句话，细节收进 `i` 图标的悬停说明。实例详情页的「导出迁移包」同样补上了「它不是备份」的对照（不进备份列表、24 小时后自动清理、不能回档），并新增「查看本实例的备份」直达按钮，跳过去会自动预选该实例。
- **已停止的实例也能手动创建存档备份**：此前手动备份不看实例状态，一律先发 `c_save()`，而停止的实例没有可收命令的进程、这一步必然失败，错误信息还写着「实例未运行或保存失败，无法创建热备份；可停止实例后重试」——实例已经停止了，照做重试仍然失败，等于这个按钮对停服的实例点不动，只有开着服才能备份。现在只有实例运行中才做热保存，停止时直接打包当前存档，与定时备份「热保存失败就按最近保存点打包」的口径一致；热保存真失败时仍然中止手动备份，不会悄悄给出一份不一致的包。
- **实例详情的「控制台」「玩家管理」挪进「房间概览」的快捷入口那一排**：这两个入口此前在页面右上角，与「刷新」排在一起，而房间设置、世界设置与 Mod 管理在卡片底部另起一排——同一类跳转被拆成两处。现在五个入口并排在卡片底部：控制台、玩家管理、房间设置、世界设置、Mod 管理。
  非饥荒实例没有房间与世界设置可进，这一排仍保留「控制台」——它本来就对所有已安装实例开放，不该因为「房间概览」只为饥荒渲染而丢掉入口。
- **内容少的页面不再拖着一大片空白**：主内容区此前被强制撑满整屏（`min-height: 100%` 配 `flex: auto`），监控台这类只有几张卡片的页面，卡片下方会留出几百像素的空区。现在内容区高度改由页面内容决定，空白消失；内容超过一屏的页面显示不变，滚动依旧由主区域承担。

### Fixed

- **从主页切到任何页面都是一片空白，只有刷新能恢复**：主内容区的路由切换动画一直用 `<Transition mode="out-in">` 包 `<KeepAlive>`，而这两者在本面板的结构下是**必然**冲突、不是偶尔撞上：`out-in` 会把「上一页还没离场完」记在一个布尔开关上，而它的渲染第一步就检查这个开关——一旦为真，内容区从此只渲染一个空占位符，之后不管切到哪个页面都不会再挂载出来，唯一恢复方式是整页刷新，且全程不抛任何错误。清除这个开关的唯一出口是「旧节点的 DOM 真的被移除」那一刻，而本面板有五个页面开了保活（监控台、实例详情、实例控制台、备份与恢复、计划任务）：从它们中的任何一个切走时，Vue 走的是 `deactivate`——节点被搬进一个隐藏容器，并不是真正移除，这个出口永远到不了。所以只要进过其中一页再切走，就会白屏。现在改成默认的交叉淡入淡出（去掉 `mode="out-in"`），不再要求旧组件必须先完全离场；同时给过渡显式声明 `:duration`，不再依赖浏览器是否派发 `transitionend` 事件。
- **离开实例详情后，它后台的轮询还在继续发请求**：详情页里的「运行时长 / 资源指标」只注册了组件卸载时的停止动作，而详情页是保活页面——切走时组件只是被停用、不会卸载，于是这两条定时器（其中一条每秒触发一次）会一直留在后台，用户人已经在别的页面，请求还在按原来的节奏发。现在把「页面被激活 / 被停用」两侧的处理补成对。
- **监控台、实例详情、实例控制台的定时器与日志流又加了一层保险**：保活组件的停用钩子只在缓存迁移时触发，而 `v-show` 隐藏、页面转场卡住、缓存被清理这三种情况都会绕过它，结果是「人都走了、后台还在重连」。现在这三页额外监听路由变化，当前路由不再是本页就立刻停下——路由变化是唯一不会漏的信号。
- `scripts/check-page-transition.mjs` 增加护栏：`<KeepAlive>` 与 `mode="out-in"` / `"in-out"` 出现在同一处时直接让检查失败。上面那个白屏的成因虽然在 Vue 内部，但在本仓库的代码里只体现为一个属性值，靠人记住它太不牢靠。
- **接口数据形状异常时，页面不再连锁卡死**：`/app/instance/list`、`/app/instance/status-counts`、实例资源指标这三个接口一旦返回非预期形状（例如 `data` 是空对象而不是数组），实例管理页会在 `instances.value.filter` / `.some` 上抛错，监控台的 CPU 卡片会在 `info.cpu.usageRate` 上抛错。而**页面组件渲染抛错之后，Vue 的卸载会连带抛错**（`unmountComponent` 读到 null），整个内容区随之停止更新——表现为**切到哪个页面都是空白、只有刷新能恢复**，也就是这次反馈的现象。现在这些取值都做了兜底：接口异常时退化为空列表与占位符，不再连锁影响整页。
- **「主页」打开后只剩顶栏，内容整片空白**：0.9.0 把主内容区的高度改成「由页面内容决定」（`flex: none`）之后，主页那个用 `absolute` + `size-full` 铺满内容区的根元素不再贡献高度——父级高度算出来是 0，再被主内容区的 `overflow: hidden` 裁掉，于是页面只剩侧栏、顶栏与一片底色。现在主页根元素回到普通文档流，滚动交给主内容区，与其他页面一致。**Mod 市场与 Mod 详情**用的是同一种写法（`absolute inset-0`），同一版本下也会整页白屏；这两页改用 layout 新增的 `--g-main-content-height` 自撑高度，整屏布局与区域内部滚动都照旧。
- **样式块里的 `//` 行注释会让开发环境的前端直接起不来**：`src/layouts/index.vue` 的 `<style scoped>` 是纯 CSS 块，里面三行 `//` 说明文字不是合法 CSS——PostCSS 在展开嵌套规则时会重新解析这段样式，于是抛 `Unknown word .main-container`，Vite 里所有页面都白屏。现在改回标准的 `/* */` 块注释，样式展开结果与原意一致。
- **「商业支持与 Pro」页现在会显示赞助说明**：服务端一直在返回「赞助是心意，不等同于购买 Pro 授权、故障处理时限或一对一支持。」这句话，界面此前没有渲染它，现在显示在「可选付费服务」区块下方。
- **面板数据库快照区块的说明文案与按钮名对齐**：区块正文此前写「由「备份面板数据」创建」，而按钮在 0.9.0 已经改名为「创建面板数据库快照」，同一块地方出现两种叫法。
- **`panel.env` 里配的多数 `GSH_STEAM_*` 与 `GSH_GITHUB_API_BASE` 根本进不了面板容器**：`docker-compose.yml` 的 `environment` 是一份显式白名单，`--env-file panel.env` 只做文件插值不做映射，于是 `GSH_STEAM_WEBAPI_KEY`、`GSH_STEAM_RELAY_URL`、`GSH_STEAM_WORKSHOP_*` 这些在 `panel.env.example` 里写着「可配」的变量，配了也全部无效——想让 Mod 市场走官方 API 或中继都没有入口。现在这些变量连同 `GSH_GITHUB_API_BASE`、以及宿主机内存判定用的 `GSH_HOST_*` 四个阈值全部补齐映射，dev compose 同步保持一份。
- **反代地址带路径前缀时会被 URL 拼接吃掉**：`GSH_STEAM_WEBAPI_BASE_URL=https://proxy.example/steam` 实际会打到 `https://proxy.example/IPublishedFileService/...`，前缀整段丢失。现在统一按「基址必须以 `/` 结尾、接口路径按相对路径拼接」处理，`panel.env.example` 里也写明了这个约定。
- `scripts/check-panel-env-presets.mjs` 增加反向门禁：`panel.env.example` 里有说明的 `GSH_*` 变量必须在 `docker-compose.yml` 的 panel 服务里被映射，否则检查直接失败——上面那类「文档写了、配了没用」的缺口不会再有第二次。
- **本地构建统一镜像在慢网络下必然失败**：镜像自带 docker CLI 与 compose 插件（约 150MB），国内链路实测只有 60~100 KB/s，下载途中会撞上中间设备处理 HTTP/2 出错（`curl: (92) HTTP/2 stream ... PROTOCOL_ERROR`）；而 curl 的 `--retry` 不重试这类错误，就算重试也是从 0 字节重来，82MB 的包重试不起，一条链路抖动就让整个构建白跑十几分钟。现在这两处下载统一走 HTTP/1.1、协议错误就地重试，并在外层做断点续传——中断后重跑，百分比从上次的位置接着涨，构建失败也不必从头再来（这一段位于 `runtime` 层最后一步，前面的层都在缓存里）。同时容器内的依赖安装调高了 pnpm 的重试次数与超时（`@iconify/json` 这类约 60MB 的包最容易被 ECONNRESET 打断），并可用 `NPM_REGISTRY=https://registry.npmmirror.com docker compose build` 指向 npm 镜像源——**不设置时仍是官方源，行为与之前一致**。排查方法见 docs/DEVELOPMENT.md「本地构建统一镜像」。

## [0.8.0] - 2026-09-22

### Added

- **插件宿主骨架：装了什么、能不能用、被授予了什么权限，现在看得见**。左侧菜单「插件」独立成页，列出插件目录下的每个插件及其状态（已启用 / 已停用 / 装载失败 / 缺少授权）、进程状态（运行中 / 已正常退出 / 进程异常）、来源（是否签名、发布方）、以及它申请的权限；启用带危险权限（启停实例、下发命令、创建备份、对外联网）的插件会先弹确认框逐条列出这些权限。插件目录默认在面板数据目录下的 `plugins/`，可用 `GSH_PLUGINS_ROOT` 指定，放进目录即可被识别，不需要命令行。
  装载校验的设计前提：**权限必须显式声明**，未声明即拒绝；**商业插件必须带签名**（`plugin.signature.json`，签的是清单的规范化 JSON），签名缺失、伪造或清单被改动都会被拒绝装载并说明原因；插件声明的接口版本与面板不匹配时直接拒绝，而不是"装了但静默失效"；**插件是独立进程**，崩溃或停用都不影响面板与正在运行的游戏实例。
- **插件现在真的会运行起来**：上一版只能识别与启停，这一版宿主会**启动已启用的插件进程**，并通过一个只监听本机回环的「能力服务」把面板数据交给插件——插件能读取实例列表、主机指标与控制台日志，**只能读它清单里声明过、且宿主已授予的能力**，越权请求会被拒绝并记录。进程与宿主的约定只有一组环境变量（插件 ID、能力服务地址、一次性令牌、接口版本），令牌每次面板启动重新生成、不落盘、不出现在命令行里。
  崩溃处理按语义分开：**退出码 0** 视为插件自己做完了事，记为「已正常退出」且不再拉起（否则一次性任务会被无限重启）；**非零退出或被信号终止**视为崩溃，按 1s→2s→4s… 退避重启，连续 5 次后停在「进程异常」并写明原因，不再重启。插件输出写到它自己目录下的 `plugin.log`，不混进面板日志。停用插件会真正终止进程；插件挂死或崩溃都不影响面板与正在运行的游戏实例。
  现状说明：插件与宿主之间提供**只读能力**（实例、指标、日志）与**一个写能力**（启停重启实例，需先声明 `instances:lifecycle` 并在启用时确认）；还没有插件页面注册协议；项目也没有随包发布的插件。
- **首页「核心能力」按菜单顺序重排，卡片直接打开对应页面**：顺序改为与左侧菜单一致（监控台 → 实例管理 → 房间 → 世界 → 玩家 → Mod → 备份 → 计划任务），并补上此前缺失的**玩家管理、模组管理、计划任务**三张卡片（游戏控制台并入「实例管理」——它挂在实例详情下，不是独立菜单项）。每张卡片的按钮从「查看文档」改为**打开面板内的对应页面**：能在面板里完成的事不该把用户送去另一个标签页，文档入口留在顶部。未登录时按钮提示「登录后打开」，权限不足时置灰并说明「当前账号无权限」，而不是点进去吃一个 403。同时删掉了标题旁多余的「v1 已支持模块一览」。
- **插件调用审计：谁调用了什么、结果如何，插件自己改不了**。宿主为每一次插件能力调用留一条记录（时间、插件、能力、操作、参数摘要、结果、耗时），落在面板数据目录的 `plugin-audit/<插件>.ndjson`——用追加写、可用 `tail`/`grep` 直接看的纯文本，而不是数据库表：**审计要比被审计的对象更耐久**。「插件」页里直接列出最近 30 条，被拒的越权尝试单独标黄。两条纪律写进了实现：**参数摘要强制脱敏**（token、password、secret、key 等键一律记成「已隐去」，长值截断、嵌套结构只记形状），因为审计文件会被打包反馈、贴进群里；**越权尝试也留痕**——拒绝本身就是需要被看到的事件。审计按插件保留最近 5000 条，超出后丢弃最旧的一半，避免长期运行写满磁盘。
- **插件现在能动实例了（受控）**：新增写能力 `instances:lifecycle`，支持 start / stop / restart。三条约束同时成立才会执行：清单里声明、面板启用时管理员确认过危险能力、每次调用都记审计。动作复用面板自身的内部逻辑（与计划任务、手动操作同一条路径），不另写"给插件用的"实现——两份实现迟早会在状态回写与安装互斥上出现分歧。
- **带了一个可运行的示例插件**：`examples/plugins/audit-reporter`，放进面板数据目录的 `plugins/` 就能启用。它演示插件开发的全部约定（清单字段、从环境变量取能力服务地址与令牌、按能力调用宿主、退出语义、日志去向），并内置一节「几个容易踩的点」。示例本身不参与构建、最容易写完就烂，因此有一条测试**把它当普通插件装载、启用、启动，检查它真的产出结果**。
- **用户操作审计：谁在什么时候改了什么，现在查得到了。** 面板会为每一次**写操作**留一条记录（时间、账号、方法、路径、参数摘要、状态码、结果、耗时、请求 ID），落在数据目录的 `audit/operations.ndjson`——纯文本追加，管理员可直接 `tail`/`grep`。三条设计取舍写在实现里：**只记写操作**（读接口量太大，会把审计淹没）；**被拒的写操作也记**（401/403 单独标为 denied——「谁在没权限时试图删除备份」比一次成功操作更值得看）；**参数强制脱敏**（token / password / secret / key 等键记成「已隐去」，长值截断，嵌套结构只记形状）。这条能力此前只存在于应用日志里，README 长期写着「查不到谁在什么时候重启了世界」——现在有了，接口是 `GET /app/system/audit/operations`。
- **第二个 Pro 插件：操作审计日志**（`examples/plugins/audit-log`）：把面板的用户操作审计按天归档成可交付的文件（NDJSON 或 CSV），可选推送到**与存档不同的一块盘**，并对敏感操作（删除备份、重置世界、踢人封禁、改配置、启用插件等）以及任何被拒的写操作告警。审计的真实痛点是**留存**——面板的审计文件有保留上限，超出会丢最旧的记录；插件补的正是这一段。同样走完整商业链路：签名验证 + 授权需含 `audit-log` + 能力 `operations:read` + 调用审计。
- **第一个 Pro 插件：异地与云备份**（`examples/plugins/remote-backup`）：定时把本机存档备份同步到**另一台机器、WebDAV 或对象存储**，按保留份数清理**远端**旧备份，失败写进状态并可发告警 webhook。几个刻意的取舍写在代码与文档里：**流式上传**（几百 MB 的包不整包进内存）、**只清理远端、绝不删本机备份**（本机备份是回滚的最后一道防线）、**失败必须可见**（写进 `state.json` 的 `lastError`，而不是静默算成功）。
  它是商业插件（`kind: commercial`），启用需要三条同时满足：清单声明所需能力、签名有效、**授权文件包含 `remote-backup`**；缺授权时面板明确显示「缺授权」而不是静默不工作。为此宿主补齐了对应能力：`/capabilities/backups`（列表，返回路径供插件自行流式读取）、`/capabilities/backups/create`、`/capabilities/backups/delete`（新增能力 `backups:delete`，属危险能力）。整条链路有 7 项端到端测试覆盖：无签名拒绝装载、签名标识不一致拒绝、签名正确装载、无授权拒绝启用、有授权后真的上传（内容逐字节一致 + 审计留痕）、上传失败写进状态。
- **授权机制（Pro 许可）已实现，且完全离线**：许可是一份带 Ed25519 签名的 JSON 文件，放在面板数据目录下的 `license.json`（或用 `GSH_LICENSE_FILE` 指定），核心用内置公钥在本地验签——**不联网、没有授权服务器、也没有回连检查**，断网环境照常生效。两条硬约束写在实现里：**Community 核心功能不因许可缺失、无效或过期而减少**，**正在运行的游戏实例永远不会因为许可问题被停止**；「商业支持与 Pro」页会如实显示状态（未安装 / 无效 / 已过期 / 有效）、客户名、已授权能力、到期时间与是否绑定设备。当前**还没有任何 Pro 功能依赖它**（插件宿主仍在开发中），所以这份许可只是把机制准备好，不影响任何现有功能。
- **系统设置新增「商业支持与 Pro」**：一页看清四件事——当前版本与版本形态、核心功能**永久免费且不做功能阉割**、可选的付费人工服务（代搭建、存档迁移、私有化部署、批量部署与年度运维、定制开发，含参考价区间与不含项）、以及 Pro 能力的真实状态。Pro（多节点统一管理、操作审计日志、异地与云备份、高级权限与角色）**仍未开发**，这里如实写明，界面其余位置不会出现任何 Pro 入口或升级提示；面板内也没有支付能力，付款与合同都在面板之外沟通。遇到故障或需要服务时，不必再去翻仓库找联系人。
  **它是独立菜单页**——设置页服务的是"面板怎么运行"，这一页服务的是"我需要什么支持"，混在一起两边都不好找。
- **迁移导出工具 `scripts/export-cluster-archive.ts`**：把一台机器上的饥荒集群存档整理成「能直接交给面板导入」的包——产出 `tar.gz`（包内顶层就是集群目录，面板的「导入存档」可直接识别）、同名 `.sha256`，以及一份迁移报告（分片、存档大小、`server_port` / `steam_auth` / `steam_master` 端口、Mod 清单与启用状态、玩家名单、令牌是否在包内，以及迁移前必须逐条确认的风险项）。工具只读源目录，**不打印集群令牌与房间密码**。从旧机器或其他面板迁服时，先跑它，再导入。
- **实例详情页「迁移到其他机器」**：不用命令行也能导迁移包——先点「检查迁移报告」看这份存档的分片端口、Mod 清单与迁移前必须确认的风险项，再点「导出迁移包」下载可直接在另一台机器导入的 `tar.gz`（同目录还有 `.sha256` 与报告文本）。报告里**不包含集群令牌与房间密码**，可以放心贴进群里或发给接手的人。包内不含游戏本体与 Mod 文件，导入后由目标机器自行下载。

- **「插件」与「商业支持与 Pro」两页的文案只留用户看得懂、能据以行动的部分**：同一件事不再在导语、区块说明和提示里各说一遍。插件页不再显示面向插件作者的接口版本号；插件卡片的说明行只在装载失败、缺授权或进程出错时出现（正常状态不再写与状态标签重复、且在进程已经跑起来之后变成错话的说明），**插件的进程侧说明因此第一次能真正显示出来**——此前它落在界面的显示条件之外，连「已正常退出」都看不到；启用与停用的提示只说动作本身，「崩溃或停用不影响游戏实例」由页面顶部常驻说明承担。商业支持页删掉与「授权状态」重复的顶部导语、与版本形态同义的第二个标签，以及底部的赞助免责声明；Pro 能力的状态由组头一句概括，各条只留「开发中 / 待随包发布」；付费服务的不含项从四条并为三条。
- **付费服务参考价整体下调，「商业支持与 Pro」页重排**：单机代搭建下调为 50～200 元/次，存档迁移、私有化部署、批量部署与年度运维、定制开发同步下调一档。这一页此前是六段平铺的说明文字加一张三列表格——窄屏要横向滚动，宽屏又拉满整屏；现在按「版本与授权 → 授权状态 → 可选付费服务 → 不含什么 → Pro 能力 → 联系方式」分组，服务改成两列卡片（服务名与参考价一行、交付内容一行），内容宽度收在 4xl 以内。页面顶部「这里要说明三件事」式的自我介绍整段删去，付费服务的排除项也只留真正影响交付的几条——服务范围写在报价单里就够了。
- **移除 `ua-parser-js` 依赖**：它只被用来给页面根元素打一个操作系统标记，而该标记全仓库没有任何消费方。移除后功能无任何变化，面板的分发链路少一个非必要的第三方依赖。
- **授权与插件改用两把密钥（推荐做法，且向后兼容）**：授权许可按**客户**签发、插件包按**发布流程**签发，两者节奏与失误面完全不同——混用一把私钥意味着一次插件签名失误会同时波及所有客户授权。现在核心支持 `GSH_LICENSE_PUBLIC_KEY`（验许可）与 `GSH_PLUGIN_PUBLIC_KEY`（验插件包）；**后者未配置时会回落到前者**，所以只配一把的既有部署不用改任何东西。两个变量都支持一次配多把（逗号或换行分隔），用于密钥轮换期同时信任新旧密钥。
- **新增插件签发工具 `scripts/plugins/sign-plugin.ts`**：一条命令给插件目录生成 `plugin.signature.json`（签名对象是清单的规范化 JSON，不是压缩包——tar 字节随打包工具与时间戳变化，签包体无法复现）。已有签名时默认拒绝覆盖，清单改动后必须重签，否则面板以「签名校验失败」拒绝装载。`generate-keypair.ts` 同时支持 `--purpose license|plugin`，从生成环节就把两把密钥分清。
- **开发机没有 Docker 时，测试不再卡死**：`test:unit` 与 `test:server` 里有一条用例会在「Docker 可用但本地没有 SteamCMD 镜像」时真的去拉取镜像，镜像拉不动的网络下整轮测试会长时间挂住且没有任何输出（实测超过 20 分钟）。现在这条用例以「镜像已在本地」为前提，不满足就跳过并说明原因，测试结果里 `skipped 1` 即来自它。两套测试在有 Docker 的机器上是全绿：1202 项与 1059 项通过、0 失败。
- **迁移导出工具增加「导入识别自检」**：导出后会用面板导入侧**真正使用的那套探测逻辑**再验一次包，并把结论写进迁移报告；包识别不了时明确提示「不要直接导入，先人工核对」，而不是等到客户上传后才发现。
- **「系统设置」这一页改叫「面板设置」，通知渠道并进它的页内 tab**：这一页管的一直是"面板自己怎么运行"（对外端口、界面主题、版本与更新、环境自检），而告警往哪儿发与它是同一件事的两半——此前分成两个菜单页，靠一排按钮互相跳转，按钮组只解决"点得到"，tab 才说明它们是同一页的两半。现在页内 tab 为「面板设置 / 通知渠道」，`/system/settings?tab=notify` 可直接深链、刷新与前进后退都停在同一个 tab 上；旧地址 `/system/notify`、`/system/commercial`、`/system/plugins` 一律重定向到新位置，书签与历史链接不会失效。
- **取消「面板设置」这个二级菜单项，页内 tab 不再改地址栏**：上一版把这一页改名叫「面板设置」是为了让 tab 说得通，但代价是侧边栏里"系统设置"底下又挂了一个"面板设置"，同一个地方两个名字。现在二级导航、面包屑与页面标题统一叫「系统设置」，点开就是这一页的全部内容。
  页内 tab 改成纯本地状态后，切 tab 不再把 `?tab=` 写进地址栏。原先每切一次 tab 都是一次真的导航：整页会按 `route.fullPath` 卸载重建（填了没保存的输入直接丢，通知渠道与操作记录跟着重新拉一遍），顶栏还会因此多出一个标签。现在切走再切回，输入还在，标签也不会平白多出来。
  旧链接照旧可用：`/system/notify` 与 `?tab=notify`、`?tab=audit` 进入时仍会落到对应 tab，随后地址栏被整理成 `/system/settings`。**为此放弃的是"刷新与前进后退停在同一个 tab"**——这两个动作现在都回到「面板设置」这个 tab，因为把 tab 写进地址栏正是上面那些代价的来源。选择用 `history.replaceState`（而非 `router.replace`）做整理，正是为了不重新触发一次导航。
- **侧边栏不再出现两个「系统设置」**：改名只解决了文字，位置没解决——这一页此前是"模块图标 + 同名子页面"两层，于是左侧同时画出了图标栏的「系统设置」和二级导航的「系统设置」，看着就是一对嵌套的同名菜单。现在这一页直接作为模块自身（不再套容器），侧边栏只留图标栏那一处，二级导航整个不再为它出现，主内容区也随之变宽。点击行为与权限不变，`/system/settings` 地址、书签与历史链接照旧可用。

### Fixed

- **「商业支持与 Pro」「插件」在菜单里点不到**：这两个页面此前在「系统设置」组下都是隐藏项（菜单只显示一个「系统设置」入口），只能靠设置页里的按钮跳转；把按钮挪走后它们就成了"路由可达但无处可点"的死页面。现在它们各占一个一级菜单入口，通知渠道并进设置页的页内 tab，页内按钮组随之取消——**页面本身就是菜单项，不再需要靠某个页面的按钮维持可达性**。另加一条护栏：每个主导航模块下至少要有一个可见页面（`meta.menu !== false`），否则模块只会在侧边栏里显示一个同名容器、真正的页面点不到；新结构下若有人再把某个页面标成隐藏项并删掉入口，测试会直接拦住。
- **房间名是中文时，迁移包导出直接失败**：下载响应头 `Content-Disposition` 里带非 ASCII 文件名会让 Node 抛 `ERR_INVALID_CHAR`，表现为**接口 500、点了导出什么都没下到**。现在响应头按 RFC 5987 同时给出 ASCII 回退名与 `filename*=UTF-8''…`，并把响应头里的换行等字符改写掉（防注入）；所有下载接口（备份、控制台日志、实例文件、迁移包）共用这一个出口。另外迁移包文件名改为 `migration-<实例后缀>-<集群目录>.tar.gz` 这种纯 ASCII 形式——中文房间名在 HTTP 头、浏览器下载与 `scp` 之间会被反复改写，而它本来就在报告第一行写着。
- **迁移报告里的 Mod 工坊 ID 少了前缀**：报告写的是 `123456` 而不是 `workshop-123456`，直接粘到工坊搜索或 SteamCMD 里都用不了。现在按工坊实际形式输出。

## [0.7.0] - 2026-09-21

### Added

- **世界地形图**：「世界设置 → 地形图」可以把**当前世界的地形**导出成一张图，用来选址、看地形分布、留档。图是从**正在运行的游戏**里读出来的：面板让专用服把每个格子的地块类型读出来发回面板，再自己渲染成 PNG，因此反映的是游戏眼里真实的地形，不是估算。图上带导出时间、地图尺寸、世界种子与已探索地块占比。几个边界先说清楚：**实例停止时无法生成**（没有活着的世界可读，界面会直接说明）；图里**含当前启用的 Mod 影响**；**不显示玩家位置**。同一张图三分钟内重复查看不会再去打扰游戏，点「重新生成」可强制重画。

## [0.6.17] - 2026-09-20

### Added

- **世界种子可以自己填了，也能一键按它重开一张图**：DST 本身不提供填写种子的入口，此前想复现一张地图只能绕开面板去改服务器上的游戏文件。现在「世界设置 → 世界生成」给出一个**世界种子**输入框：实例运行中它锁定并显示当前世界正在用的种子（面板会自动从游戏读取并记下来，**停服后依然显示**）；停止后即可修改，改完点旁边的**重置世界**，面板会先自动创建一份安全备份，再丢弃当前世界、按这个种子重新生成地图并启动实例，留空则由游戏随机。想复现同一张地图，除了同一种子还需要同一套世界生成参数与同一份 Mod 组合。「世界维护」里的**重置世界**保持原样：把命令发给运行中的游戏快速重开一张图，不改种子、也不需要停服。

### Fixed

- **容器模式下不再白等 15 分钟才启动洞穴**：主世界就绪判定此前只在「已探测到分片端口」的前提下才去读世界就绪标记，而那个端口（`cluster.ini [SHARD]` 的 `master_port`）只在实例容器的网络里监听、**从不发布到宿主机**（发布的是 `server.ini` 的三个游戏端口），面板在容器里探测它必然为空。于是「端口已被占用」这条判据永远不成立，就绪标记也永远不会被检查：房间能进、控制台却一路报「主世界仍在加载（…尚未监听到分片端口）」，直到 900 秒超时兜底才启动洞穴。现在改为以 DST 自己写的 `server_log.txt` 就绪标记为主判据（命中即放行，容器与 native 部署都成立），端口探测降级为辅助判据，只在面板与游戏处于同一网络命名空间（native 同机进程）时才用来兜底；等待期间的心跳文案也由「尚未监听到分片端口」改为「尚未看到世界就绪标记」，不再把「探测不到」说成「没在加载」。

- **「发现 N 个 Mod 有新版本」却找不到任何可更新的行**：面板能看出「服务器实际加载的 Mod 文件比已下载内容旧」（DST 专用服只读 `ugc_mods`，落位被跳过时两份内容会不一致），可这个结论此前只写在本次检查的响应里、没有入库——列表刷新后又按两个时间戳算出「已是最新」，于是通知说有新版本、工具条却显示「全部更新 (0)」、每行都没有「更新」按钮，用户被卡在「检测得到却更新不了」。现在该判定随检查结果一起入库（`instance_mods` 新增 `loaded_copy_stale` 列，升级时自动补 0），列表与通知口径一致，点「更新」即可重新下载并按新内容重新落位，重启实例后生效。
- **「检查更新」不再把没查出来的 Mod 说成「本地都是最新版本」**：面板的版本结论只在「本机内容凭据」与「工坊版本时间」都拿到时才成立，信息不足的条目一律是「未检查」。可提示语只看「这次有没有发现新版本」，只要 `outdated` 为 0，就把 `M 个已是最新` 与 `N 个未检查` 一起说成「当前 Mod 都是创意工坊上的最新版本」——列表里那些挂着「未检查 / 重新下载」的行被这句话盖过去，用户带着一台装着旧 Mod 的服务器开服，玩家进服时被「服务器启用了一些旧版本的 Mod」挡在门外。现在两者分开说：只有全部判定完成才报「都是最新」，还剩没判定的就明确写出数量并指向「重新下载」。
- **本机 Mod 版本改用内容凭据，不再拿「面板记录这份内容的时间」冒充版本时间**：本机版本此前读 SteamCMD 清单 `appworkshop_322330.acf` 里的 `timeupdated`，清单里没有这个条目时回落到「面板记录该 Mod 的时刻」——而记录时刻必然晚于当时的工坊版本，两侧一比只会得到「已是最新」，真正存在的旧版本被永久漏报。现在改为清单优先、其次用内容文件的落地时间（`steamapps/workshop/content/322330/<id>` 里 `modinfo.lua` 等的 mtime），两者都取不到就老实回答「无法判断版本」。
- **「更新」之后再也不会自证「已是最新」**：强制更新成功时面板会把本机时间同时写成远端时间，等于替工坊宣布「两边一致」；SteamCMD 空跑、内容没真正换掉时，这一步会把旧内容锁死在「已是最新」。现在远端只写工坊给出的时间，本机内容是否已追平由两侧时间比较得出——更新没生效就会停在「有新版本」，而不是被抹平。
- **游戏实际加载的那份 Mod 也纳入检查**：DST 专用服只读 `ugc_mods`，而落位在目标目录已存在时会跳过，于是「下载目录已是最新、游戏里读到的还是旧内容」可以同时成立，只看下载目录的面板发现不了，玩家照样被版本校验拦下。现在检查更新会比对两份内容的落地时间，游戏那份更旧即判「有新版本」，并说明需要重新下载、由面板重新落位后再重启实例。
- **SteamCMD「失败但退出码为 0」不再算下载成功**：日志里已经写着 `ERROR! Failed to download` / `Access Denied` / `No subscription` / `Missing file permissions` 时，进程仍可能正常退出，而本机旧文件还在盘上，文件存在性检查看不出问题——这次更新会被记成成功、状态改回「已是最新」。现在这类输出直接判失败，等待重试。

## [0.6.16] - 2026-09-19

### Added

- **面板升级后，旧页面会自己说「我是旧版本」**：面板是长时间驻留的单页应用，升级只会换掉服务器上的前端产物，**已经打开的标签页仍在执行升级前的脚本**——此前升级流程里没有任何重新加载页面的动作，也没有版本自检，于是升级成功后继续看到旧界面（旧按钮、旧文案），很容易误判成「新功能没生效」。现在页面会用自身构建版本与面板上报的版本比对（每分钟一次、切回标签页时立即一次），不一致就弹出常驻提示「页面还是旧版本」，点「刷新页面」即加载新界面。为不打断正在填写的内容，**只提示不自动刷新**。

### Fixed

- **「已下载·待开启」不再自相矛盾**：Mod 列表的安装状态此前把两件事塞进一个标签——文件有没有下好（安装状态）与在世界里有没有开启（开关状态），而后者本来就紧挨着另占一列，于是明明写着「已开启」的行仍然显示「待开启」。现在安装状态只回答文件问题（**已就绪 / 下载中 / 下载失败**），列名在两处页面统一为「安装状态」，悬停可看到两列的分工说明；「还要去世界设置开启」的引导仍保留在订阅成功的提示里。
- **前端入口页明确不缓存，挡住「升级了但界面没变」的另一条路**：`index.html` 是唯一没有内容哈希的文件，此前依赖静态服务的默认缓存头，一旦被浏览器或中间代理按 `max-age` 缓存住，升级后页面仍会去加载旧脚本。现在明确声明它为 `no-cache`，带哈希的 `assets/*` 声明为长期 `immutable`；同时补上了此前**从未注入**的前端构建版本（`系统信息` 抽屉里的「版本号」因此从空白变为正常显示）。

## [0.6.15] - 2026-09-19

### Added

### Fixed

## [0.6.14] - 2026-09-17

### Added

- **监控台补上缓存区与「可用缓冲」**：小内存机上真正决定「还能不能再起一个分片」的，不是内存占用百分比，而是可用内存加上缓存区余量还剩多少——此前面板完全不显示缓存区，`free -h` 里 `Swap` 快用满时界面看不出任何异常。现在内存卡片同时显示缓存区用量与「可用缓冲」，低于 1 GB 转为警示色、低于 0.5 GB 标红并提示重启实例可能被拦下；未配置缓存区时显示「未配置」，不与「配置了但用满」混为一谈。

### Fixed

- **内存使用率改用「可用内存」口径，和 `free -h`、启动守卫说同一句话**：此前面板用 `MemFree` 计算，而它不包含可回收的文件缓存——4 GiB 机器读过几 GB 游戏文件后就会显示 95% 内存占用，同一台机器上的启动守卫却按 `MemAvailable` 判断「还能再起一个分片」，两边自相矛盾。现在统一为「已用 = 总量 − 可用（MemAvailable）」，节点卡片、监控台、通知阈值与自检读的是同一个口径，内存告警不会再因为文件缓存误报。
- **CPU 读数不再互相偷采样窗口**：`/proc/stat` 的「上一次读数」此前由每次请求推进，节点卡片（10 秒轮询）、监控台（10 秒轮询）与阈值检查（60 秒）会互相把窗口切到几十毫秒，同一时刻两处显示的数字因此不同；面板刚启动时的第一个数字还会退化成「开机以来平均值」。现在由后台每 3 秒固定采样一次，所有位置读同一个窗口。
- **编辑通知渠道时留空不再清掉已配置的字段**：此前对「已配置但留空」的字段也会提交空字符串，而后端把显式空字符串当作清除该键——编辑渠道时只要不动输入框保存，就会把原配置清空，必填项还会被「缺少必填配置」拦下，与界面自己写的「已配置（留空保留原值）」正好相反。现在留空即保留原值。

### Changed

- 监控台内存卡片补上「可用」数值；实例卡片的 CPU 标注为**单核基准**、内存标注为**主世界进程**常驻内存——这两个数字与监控台的全核基准不可直接比较，标注出来省得对不上号时误判成采集出错。

## [0.6.10] - 2026-09-17

### Fixed

## [0.6.5] - 2026-09-17

### Fixed

- **主世界不再被内存尖峰杀掉**：主世界与洞穴原先同时加载，各自都要把整套 Mod 与世界读一遍，两个峰值叠在一起会把整机内存吃穿——线上实测主世界分片 `anon-rss` 涨到 2.0 GiB 时被内核 OOM 杀掉，随后 systemd 立刻把它拉起来重跑，永远到不了「世界加载完成」。现在主世界先启动，面板轮询它的分片端口（`cluster.ini` 的 `master_port`），确认就绪后才拉起洞穴；主世界若在加载途中退出，则中止本次启动并清掉残留分片，而不是留下「洞穴单独在跑」的残局。
- **分片崩溃不再无声地吃掉整机 CPU**：进程每崩一次 systemd 都会在 5 秒后重来，每次都重新吃满 CPU 与磁盘加载整套 Mod。现在 10 分钟内最多拉起 3 次，超过就停手并在实例上写明原因；用户手动点击启动会先清掉这个计数，正常重启不受影响。
- **面板与 SSH 不再被游戏饿死**：两个分片各占满一个核时，2 核机上留给面板和 sshd 的 CPU 是零——线上出现面板连续 69 秒写不出任何日志、只能靠 SSH 排查的情况。现在分片会按整机核数分配 CPU 配额，始终给面板留出余量。
- **内存软限与缓存区**：分片单元同时下发 `MemoryHigh`（软限）与 `MemoryMax`（硬限），并允许使用缓存区，让加载尖峰走回收/换页而不是被直接杀掉。
- **启动前的内存估算按真实规模来**：原先固定按单分片 512 MiB 判断，36 个 Mod 的双分片启动被轻易放行、然后在加载途中被内核杀掉。现在按「分片数 × （512 MiB + 每个启用中的 Mod 32 MiB）」估算，并把可用缓存区计入可回收余量；不够时直接拒绝启动，同时给出加缓存区、关洞穴、减 Mod 三条可执行建议。
- **崩溃原因不会再被一秒后擦掉**：运行期警告改用独立字段保存。原先它与「启动失败」共用 `lastError`，实测「主世界分片已停止，但洞穴分片仍在运行」写入一秒后就被状态对账清空，服主永远看不到。现在该字段只在实例连续干净运行 30 分钟后才自动消失。
- **实例状态不再在两类对账之间来回翻**：systemd 的 5 秒自动拉起窗口会被第二趟对账当成「容器还在跑」，把刚写成「已停止 + 崩溃告警」的实例翻回运行中。现在处于自动拉起或已经重启过的分片一律按崩溃循环处理，只告警不复活。
- **面板控制台终于能看到游戏输出**：分片日志原先走 `journalctl --user-unit`，而面板以 `gsh` 用户跑在系统服务里、不在 `systemd-journal` 组内，必然报「No journal files were opened due to insufficient permissions」。现在 systemd 直接把分片输出追加到面板可读的日志文件，日志跨重启累积，上一轮崩溃的现场不会再被覆盖。

## [0.6.4] - 2026-09-16

### Fixed

- **Native 部署的「下载更新」不再一声不吭**：Native 的更新包下载段从来没有把状态推进到「下载中」，界面因此既不显示「已下载 12 MB / 44 MB」，下载完成时也不会提示——只能靠刷新页面才知道已经下好。现在它与 Docker 走同一条阶段链路（准备 → 下载中带进度 → 已就绪），进度数字与「更新已下载，点『立即安装』」的提示都会正常出现。
- **实例不再在「运行中 / 已停止」之间来回跳**：分片单元是「失败即重启、重试间隔 5 秒」，进程崩溃后单元会在等待重启的窗口里短暂不是 active，而面板探活只认 active——于是每轮对账都把它改成「已停止」，5 秒后又改回「运行中」，在列表与详情之间切换就会看到两种状态。现在「等待重启」同样算运行中；探测不到运行时（运行时本身不可达）时保持现状，不再把运行中的实例误判成已停止。
- **实例反复重启时明说，而不是显示成一切正常**：反复崩溃又反复被拉起时，界面长期显示「运行中」，服主会以为房间正常，实际玩家根本连不上。现在会把重启次数与退出原因（例如内存不足被终止）写到实例上并以警示色显示；主世界已停、洞穴分片却还在跑时也会直接指出来，免得残留的洞穴白占内存。
- **Native 控制台不再只剩一句权限报错**：面板读不到系统日志时，原先只会显示那句「没有读取权限」；现在换成「完整日志在实例目录的 …/server_log.txt」，明确告诉你去哪找崩溃原因。
- **服务端不再每次启动都去创意工坊重抓一遍 Mod**：面板本来就负责把 Mod 下载好、放进服务器的加载目录，但启动参数里少了官方提供的「跳过 Mod 更新检查」，于是游戏每次启动都会照着 Mod 清单联网校验并抓取一遍。Mod 一多，CPU、带宽和磁盘就被同时占满，小机器上直接陷入「启动 → 超时 → 崩溃 → 重启」的循环，玩家始终连不上——同一份存档在别的面板上能跑、在这里跑不动，差别就在这里。

## [0.6.3] - 2026-09-16

### Fixed

- **导入存档后不再把没下载的 Mod 当成「已就绪」**：导入外部存档时，面板把源档里的每个 Mod 都记成已就绪，并不检查创意工坊内容是否真在这台机器上——于是房间概览显示满员、Mod 页整列绿灯，进游戏却只加载出有文件的那几个（剩下的交给服务器启动时自己补下载，老式包常超时失败）。现在导入按磁盘实际情况判定：内容在的才记已就绪，其余记为等待下载并自动排进下载队列。

- **房间概览的 Mod 数字改成「已生效 / 总数」**：以前只数开关，没下载下来的 Mod 也算进去，看上去总是满员。现在只有文件就绪且开关打开的才计入，旁边直接标出还有几个未就绪。
- **导入存档的 Mod 名称不再是一串 workshop 编号**：内容落地后从 Mod 自己的信息文件里读出真实名称并回写（此前列表里显示的是 `workshop-1185229307` 这种目录名）。

## [0.6.2] - 2026-09-16

### Fixed

- **下载日志、备份与实例文件不再得到 0 字节的空文件**：三个下载接口的响应被 Fastify 当成「handler 什么都没发」，于是以空响应收尾（HTTP 200 + `Content-Length: 0`）——点「下载日志」只会存下一个空文件，备份下载与实例详情页的文件下载同样中招。现在三处走同一条下载出口，下载到的内容与服务器上的文件完全一致。
- **在线玩家列表不再漏掉「路人」**：没有 Klei 账号的玩家（离线或局域网进来的）以前只被算进人数、进不了明细，于是出现「实例详情说 1 人在线、玩家管理页说没人」。现在他们会以「临时身份」正常列出，可以踢出；封禁与加入名单仍只对 Klei 账号开放，因为临时 ID 每次进服都会变。两个页面的人数也就此统一到同一个读数，游戏连临时 ID 都没给的会单独提示「另有 N 人无法列出」。
- **实例详情的在线玩家不再少算洞穴里的玩家**：这一处以前只查地上分片，玩家走进洞穴后详情页的人数会少一个；现在它与玩家管理页走同一条查询路径，两个页面的人数和明细完全一致，只查到一侧时明细卡片也会如实提示「列表可能少人」。
- **带 `-` 的玩家 ID 不再被当成非法**：Klei 账号形如 `KU_3rpxG-xy`，而面板里有六处把 ID 的字符集写成了「字母、数字、下划线」，真实账号因此被判成非法——在线列表把他标成「临时身份」并禁用封禁，踢出与加入名单也一律被拒。字符集已收敛到一处并补上 `-`，这类账号现在能正常显示与操作。
- **「房间玩家」页顶部的「房间设置」按钮去掉了**：白名单没启用时那句警告里的「房间设置」现在可以直接点，进的就是这个实例的房间设置页——入口跟着要改的地方走，不必先记住它在导航的哪一层。
- **玩家名单为空时不再多一句「当前还没有任何条目」**：卡片上已经写着「名单为空」，那句说明是多余的。
- **手动备份点下去就有反馈了**：点「开始备份」后弹窗立刻关闭，而打包存档要等几十秒（运行中的实例还得先让世界保存一次），这段时间界面毫无动静，很容易被当成没点上而重复点击。现在提交期间「创建存档备份」按钮进入等待状态，页面顶部同时挂一条「正在备份存档，请稍候…」，完成或失败时这条提示原地变成结果；「备份面板数据」同样处理。
- **大存档的备份不再被 60 秒请求超时误判为失败**：创建备份、恢复、导入、面板快照与备份下载都要等后端把存档打包或解压完才返回，档案一大就超过全局 60 秒超时，前端弹出「请求失败」而后端其实已经成功。这几个接口现在与存档上传接口一致，不再设请求超时（列表与删除很快，仍保留全局超时）。
- **导入外部存档时不再同时出现两个转圈**：上传过程中文件名后面与识别区各有一个转圈，再加上传进度条，三处一起转反而看不出到底在忙什么。现在只保留进度条。
- **Native 部署下实例一个都启动不了（systemd 只回一句 `has a bad unit file setting`）**：面板生成分片 unit 时给 `WorkingDirectory=` 加了双引号，而 systemd 对这一行**不做去引号处理**——它把 `"/srv/.../bin64"` 整串当成路径，判定「非绝对路径」后直接把整个 unit 判为非法。表现是新建实例第一步就失败、与是否导入存档无关，界面也看不出是哪一行。现在这一行不再带引号（`ExecStart=` 走 shell 风格分词，引号合法，两行分开处理）；值里的 `%` 统一转义为 `%%`（systemd 会做 specifier 展开，路径含 `%` 同样会让 unit 非法）；资源限制写入前钳到 systemd 接受的范围（CPUQuota 1%–10000%、MemoryMax 不小于 1 MiB）；并去掉用户级实例里并不存在的 `network-online.target` 依赖。
- **Native 启动失败不再只给一句看不出原因的 systemd 报错**：面板会附上 `systemd-analyze verify` 的自校验输出、`systemctl --user status` 原文与 unit 文件内容（超长截断），界面和日志里直接能看到 systemd 嫌哪一行；Native 的报错也不会再被 Docker 的镜像提示顶掉。
- **停止与删除实例点下去立刻有反馈**：确认弹窗一关就只剩列表按钮转圈，而停止要等在跑的进程落盘退出、删除还要先停实例再清目录，等待期间看起来像没点上。现在会挂一条「正在停止实例，请稍候…」／「正在删除实例，请稍候…」，完成或失败时这条提示原地变成结果。

## [0.6.0] - 2026-09-16

### Added

- **玩家管理成了一个独立页面，名单改用游戏名显示与搜索**：此前玩家管理分散在两处——名单在「房间管理 → 房间设置」里维护，踢人与封禁在「实例管理 → 实例详情」的卡片上；两处都只认 `KU_` 开头的玩家 ID，加人之前得先去控制台或日志里把 ID 找出来，加完也认不出加的是谁。现在左侧导航新增一级 **玩家管理**：先列出各房间，进入某个房间后，在线玩家（地上与洞穴分开）与管理员 / 白名单 / 黑名单三份名单在同一页。名单里显示的是**游戏名**，加入时可以直接填名字（面板会列出匹配到的玩家让你确认），也可以粘贴一个或多个玩家 ID，还能把在线的某人一键加进白名单或设为管理员。面板会记住「玩家 ID ↔ 游戏名」的对应关系：玩家在线时自动记录，点「从日志补全玩家名」还能从服务器日志里把历史记录捞回来；从未在本服出现过的玩家查不到名字，可以填 ID 再加入，也可以给这条记录加一个只存在面板里的备注名。名单文件写入的仍然是玩家 ID，游戏侧行为不变。
- **玩家名单与在线玩家的入口收敛**：房间设置页原来的名单区块改为一段说明与跳转入口，实例详情页的「在线玩家」卡片改为只读概览（保留人数与名单，操作统一到玩家管理页），避免同一件事有两个入口、两处状态还不一致。
- **文件管理支持上传与下载**：可以把本地文件直接传进当前所在目录（例如改好的配置传回 `Cluster_1`），也可以把单个文件下载取走；上传同名文件会**先备份再覆盖**，两者都有进度提示。上传目标同样受实例沙箱约束（文件名不能带路径分隔符、目录不能越出实例目录），集群令牌等敏感文件不提供上传覆盖与下载；单文件上传默认上限 256 MiB，可用 `GSH_INSTANCE_UPLOAD_MAX_BYTES` 收紧。整套存档的搬迁仍建议走「备份与恢复」，它会把世界数据、房间配置与令牌一起打包。

- **控制台日志会落盘，可查看历史与下载**：此前控制台日志只在面板内存里保留最近 2000 行，**面板一重启记录就没了**——半夜掉线、崩溃重启这类问题第二天基本无从查起。现在日志同时写入 `<数据目录>/install-logs/console/<实例 ID>.log`（每行带时间、分片与来源标记），单文件超过 5 MiB 自动轮转、保留当前加两个历史文件，删除实例时一并清理。控制台页新增「历史日志」（查看末尾 500 行，面板重启前的记录也在）与「下载日志」（取走整个文件，方便贴给别人或长期留存）。
- **通知渠道新增通用 Webhook 与 Telegram**：通用 Webhook 会向你的 https 地址 POST 结构化 JSON（`source`、`severity`、`title`、`message`、`text`、`at`），便于接自建告警或中转；Telegram 填 Bot Token 与 Chat ID（群组为负数，频道可用 `@频道名`）即可推送到手机。同时把渠道配置校验提前到保存时：Webhook 必须 https，Bot Token 与 Chat ID 形状不对会直接拒绝，而不是等到事件触发才发现渠道一直是失败的。
- **实例详情页新增「文件管理」**：可以浏览实例目录、直接编辑文本配置（房间、世界、Mod 等 `.ini` / `.lua` / `.json` / `.txt` / `.cfg` / `.log`），并支持重命名与删除。卡片顶部还给出**关键配置文件的直达入口**（房间配置、地上 / 洞穴的世界与 Mod 配置，文件存在时才显示），不必在目录树里翻路径。保存前自动备份原文件（同目录生成带时间戳的 `.bak`），单个文本文件读写上限 1 MiB（超出只显示前 1 MiB 并提示）；集群令牌等敏感文件标注「敏感」，不提供查看、编辑、重命名与删除。文件操作全部限制在实例目录内：绝对路径、`..` 与指向目录外的符号链接都会被拒绝。**上传与下载仍不在面板内提供**，搬运文件请用「备份与恢复」或 SFTP。
- **世界设置页新增「世界维护」**：可以看到当前分片读到的存档点数量与时间，按步数回档，以及重置世界。两个危险操作都会**先自动创建一份安全备份**（分别标记为「回档前」「重置前」），回档过头或重置错了都能在「备份与恢复」里翻回来——此前只有控制台与命令中心能下发这两条命令，确认弹窗明说"不可恢复"。重置世界需要手动输入实例名称二次确认，回档步数受房间设置里的「最大快照数」约束。
- **房间设置页新增玩家名单管理**：可以维护管理员、白名单与黑名单三个名单，填入 `KU_` 开头的玩家 ID 即可加入或移出，改动立即保存、不需要再点保存按钮。同时新增「白名单预留位」设置——此前该值固定为 0，白名单即使填了名单也不会生效；现在填一个大于 0、且不超过最大玩家数的数字即可启用白名单，白名单未启用时页面会直接提示。
- **实例详情页新增「在线玩家」：看清谁在房间里，并直接踢出或封禁**：此前面板只知道"有几个人在线"，不知道是谁——玩家名单里空无一人、在线人数却是 1 的时候尤其容易误解（名单是准入配置，不是在线花名册）。现在详情页会列出每位在线玩家的名字与 Klei 玩家 ID（`KU_` 开头），每人两个操作：**踢出**立刻把对方移出房间，对方可以马上重连，适合临时清场或让卡住的玩家重连；**封禁**把对方写入黑名单并同时踢出，写入的就是「房间设置 → 玩家名单 → 黑名单」那一份名单，两处内容始终一致。两个操作都有确认弹窗，也都能在控制台日志里看到对应的命令回显。**封禁不阻止当前这条连接重连**：黑名单要等房间重启后才会在准入时生效，想立刻彻底挡住请在封禁后重启房间——界面提示里也写了这一点。

### Changed

- **踢人改用官方服务端命令，并且不再谎报成功**：此前踢出走的是 `c_kick("KU_xxx")`，而这条命令并不在游戏服务端的控制台脚本里——命令确实送进了游戏，游戏只打印一条 Lua 报错就什么也不做，面板却提示「踢出命令已送达房间」，于是出现「提示成功、人还站在原地」。现在改用官方命令表的 `TheNet:Kick(userid)`，并在下发后**复查在线玩家**：只有确认对方已经离开才提示成功；没确认到就如实说「命令已下发，但复查时该玩家仍在房间里」，同时把游戏返回的报错线索一并带出来，方便判断原因。
- **封禁立即生效，不必再重启房间**：此前封禁只写黑名单文件，而该文件仅在房间启动时读取，所以必须重启才能挡住人。现在封禁会同时下发 `TheNet:Ban(userid)`——立刻踢出、立刻拒绝重连，黑名单文件照旧写入，房间重启后依然生效。若房间没有运行或命令没送达，界面会如实说明「已写入黑名单，但即时封禁命令未送达」，不让人误以为已经挡住。
- **在线玩家、踢人与封禁支持洞穴分片**：地上与洞穴是两个独立进程，玩家列表互不可见——此前面板只查地上世界，玩家走进洞穴后就既看不到也踢不掉。现在在线玩家按「地上 / 洞穴」分别列出并标注所在世界，踢人与封禁按玩家实际所在的分片下发命令；封禁命令固定发往主世界（封禁名单由主世界管理）。某个分片查询失败时界面会提示这次列表可能不全，而不是把「没查到」当成「没人在线」。
- **控制台的「面板与控制」与「运行日志」合并为一个「控制台」页签**：此前命令要在一个页签里输入、执行结果却要去另一个页签查看，调一条命令就得来回切换；现在命令回显与执行结果在同一个日志视口里按时间排列，回显行用琥珀色文字与左侧竖线标出，便于在密集的游戏日志里定位自己刚发的那条命令。原有「运行日志」的能力没有丢——日志区上方新增「显示」过滤，可在**全部 / 面板消息 / 游戏输出**之间切换，默认「全部」，「复制日志」复制当前可见的内容。同时修掉一个隐患：实时日志流中断后按页签兜底拉取时，另一类日志会被永久跳过（表现为日志莫名缺失），现在固定按全量拉取。

### Fixed

- **踢出不再踢错人：跳过服务器自己的 `[Host]` 连接**：专用服务器自己也是一条连接（名字显示为 `[Host]`），当集群令牌用的就是房间里某个玩家的账号时，它和那个玩家会撞上同一个玩家 ID——此时 `TheNet:Kick(该 ID)` 踢到的是服务器自己那条假连接，**玩家一动不动，游戏也不会报任何错**，看起来就像「点了踢出没反应」（实测日志里两条连接同为 `KU_xxx`，一条 `host=true`、一条 `host=false`）。现在下发前先按官方脚本的规则过滤掉带 `performance` 的占位连接。
- **房间主人自己改用「移出世界」**：房主那条连接就是服务器本身，断开它在游戏里根本做不到（`TheNet:Kick` 会落到假连接上）。面板认出这种目标后改用官方的 `c_despawn`——它内部先按 ID 跳过 `[Host]` 找到玩家实体，把人送回角色选择界面，玩家数据照存档保留，重新选角色即可再进。界面会如实说「已把「某某」移出世界」，而不是假装踢了一脚。
- **封禁不会再把自己关在门外**：黑名单是按玩家 ID 写的，如果被封的正是房间主人自己的账号（集群令牌属于它），重启后他自己都进不来。现在封禁会在**写名单之前**先认出房间主人并拒绝，界面直接说明原因；而踢出这一步在失败时会把游戏侧的连接表抄进面板日志，下次排查不用再手敲诊断命令。
- **踢出 / 封禁的提示改回一句人话**：此前失败时会甩出「命令已下发，但复查时该玩家仍在房间里，可能命令未被执行或他正在另一个世界（地上／洞穴）。请刷新后再试一次。（已补发 1 次……）」这类又长又要管理员自己消化的话。现在只有三句：`已踢出「某某」`、`没能踢出「某某」，请改用封禁`、`没能确认结果，请刷新在线列表`——命令原文、游戏输出、复查结果这些技术细节写进面板日志与服务器日志，不再占用界面。
- **面板会先自检「命令到底进没进游戏」**：每次踢出 / 封禁前，面板先往游戏里写一条最短的探针，确认它真的被执行了；没有回声就直接说「面板发不出命令到房间，请重启面板后重试」，而不是让管理员一遍遍点踢出、猜是游戏的问题还是面板的问题。
- **踢出与封禁的确认弹窗按钮会转圈**：这两个操作要下发命令再复查在线名单，成功要一两秒、失败更久，此前面板毫无反馈，点下去像是没反应，容易连点几次。现在按钮进入等待（同时禁用、弹窗不会误关），结果出来才关闭弹窗并给出提示。
- **移出黑名单现在会一并处理"人在门外进不来"的问题**：游戏只在启动时读取黑名单，运行中的房间把封禁记在内存里——此前从黑名单删掉某个 ID 只改了文件，被移出的人仍然被拒绝加入，看起来像"移除了却还进不去"，只能自己想到去重启房间。现在房间运行时点「移出」，面板会说明这一点并直接问要不要**移出并重启房间**；选择只移出时也会提示"需要重启房间后该玩家才能重新加入"。（游戏没有运行时的解封命令，重启是唯一途径。）
- **名单里的玩家名会自动补全，不再显示成一串 ID**：此前只有打开「在线玩家」或手动点「从日志补全玩家名」才会采集名字，历史名单条目与"加人时玩家不在线"的条目一直是「（未取名）」。现在打开玩家名单就会顺手从日志里补一次名字（同一实例 30 秒内只扫一次），踢人/封禁时探测到的名字也会立刻记进档案。
- **从日志补名字不再可能写入假名字**：实测真实服务器日志里并没有「玩家 ID + 名字」同行的记录，只有 `Received (KU_xxx) from TokenPurpose` 这类**不含名字**的行——按"ID 后面那截就是名字"去猜，档案里会出现「from TokenPurpose」。现在只认两种可信来源：面板自己注入的在线查询标记行（`GSH_PLAYER_LIST_ITEM:...`，制表符分隔）与部分版本的 `Client authenticated: (KU_x) 名字`，其余行一律忽略。
- **点「下载日志」不再把用户踢出登录**：下载类接口（控制台日志、备份、实例文件）返回的是文件本体，前端却把它当成 `{ status, data }` 业务响应解读——文件对象没有 `status` 字段，于是被判定为「登录状态失效」，请求成功了页面也会直接登出跳到登录页。现在这类二进制响应原样透传给调用方，下载正常落盘、页面不再跳转；Docker 与 Native 部署共用同一份前端代码，此前两者都受影响，一并修复。
- **下载失败时显示后端给的真实原因**：同一条下载链路失败时，后端返回的中文原因（例如「还没有可下载的日志，实例启动过一次后才会生成」「备份包文件已丢失」）被响应体的二进制包装吞掉，界面上只剩一句 `Request failed with status code 404`。现在失败原因按业务语义读回并如实提示；顺带修好这类请求遇到未授权时的会话刷新与「首次登录须修改初始密码」跳转——此前它们同样因为读不到 `code` 而失效。
- **停在其它页面时不再被自动顶回「实例管理」**：实例详情页与控制台页开了页面缓存，离开后组件并不销毁——详情页的 30 秒概览轮询还在后台跑，而它此时读到的实例 ID 已是别的页面的值（或已为空），于是判定「实例不存在」并跳回实例管理列表，表现为"人在世界管理页，几十秒后自己跳走了"；控制台页同理会后台重连实例日志流。现在离开这两个页面即停止后台轮询与重连，且后台不再替用户跳转：只有真在该页面上时才会提示「实例不存在或已删除」并返回列表，回到页面后轮询自动恢复。
- **面板自身的在线人数查询不再往控制台写回显**：详情页每隔 30 秒查询一次在线人数，而每次查询都会往控制台消息区写一条 `> print("GSH_PLAYER_COUNT:...")` 的命令行回显——看起来像有人每半分钟手动发一条命令，排查问题时相当干扰。现在面板自己的周期查询改为静默下发，只有你真正发出的命令才会在控制台留下回显。

## [0.5.0] - 2026-09-15

### Added

- **Native（systemd）部署支持面板内一键更新**：此前这类部署只能去服务器终端重跑安装脚本。现在「系统设置 → 面板与游戏版本」同样提供「下载更新 → 立即安装」——面板负责下载 Native Release 包并显示进度（断点续传、官方 `.sha256` 校验，本地已有则直接就绪），真正的安装交给安装器布置的后台更新程序以 root 完成：校验面板请求的版本号、取 GitHub Release 的官方安装脚本与官方摘要、解压到 `releases/<版本>`、原子切换 `current`、更新 `panel.env`、重启面板，并核对 `/health` 的版本号确认新版本真的在运行；任何一步失败都会回滚到上一个版本并恢复原配置。只接受升级（同版本重装与降级会被拒绝）。**从更早版本升上来的实例需要重跑一次安装脚本才会获得这套组件**，没有组件时面板会明说并给出可复制的安装命令（详见 `docs/INSTALL.md` 的升级章节）。权限上做了分层：面板只能写一个「目标版本号」的请求文件，root 侧执行器的锁、日志、校验通过的包与配置备份都放在交换目录下的 root 专属子目录（每次运行重新校验属主），面板无法借符号链接或替换字节影响 root 的动作；执行器被中断（重启、超时）也会留下明确的失败状态，界面不会卡在「更新中」。

### Changed

- **手动更新的提示改成按部署方式给对的命令**：此前不论什么部署方式，提示行都硬编码 `sudo gsh update`，而它在 Native 下是一条什么都不做的命令（只打印一句警告），真正可用的安装器命令被折叠在「其他更新方式」里。现在提示行直接展示后端按当前部署方式生成的命令（Docker 给 compose 命令、Native 给带加速代理的安装脚本命令）并可一键复制；面板内更新不可用时还会说明「重跑一次安装脚本即可在面板里更新」。

### Fixed

- **粘贴工坊详情页链接订阅不再失败**：识别链接的正则写成 `filedetails?id=`，而 Steam 的实际路径是 `sharedfiles/filedetails/?id=`——中间那个斜杠让它永远匹配不上，于是输入框虽写着「粘贴工坊 ID 或详情页链接」，粘链接一定失败，只有纯数字能订阅。现在正则接受 `filedetails` 后可选的斜杠，也接受 `id` 不在首位（如 `?mod=1&id=…`）。
- **Native 升级后仍在跑旧版本**：升级时安装器把 `current` 符号链接切到了新 Release，但 `systemctl enable --now` 对已在运行的服务是空操作，面板进程还停在旧代码上，健康检查也因此发现不了。现在安装器在升级路径上会 `try-restart` 面板服务，后台更新程序也会核对 `/health` 里的版本号后才判定成功。
- **刷新页面后更新进度不再卡在「更新中」**：进入或重新激活「系统设置」页时只拉一次状态、不恢复轮询，若上次会话留下的状态是「更新中」（面板正在重启或更新仍在跑），界面就会一直停在那里。现在发现状态为「更新中」便自动恢复进度轮询。
- **世界设置与房间设置底部的三个按钮不再共用一个 loading**：此前底部固定栏的「重置 / 保存 / 保存并重启」共用同一个请求中状态，点「保存地上」时「保存并重启」也在转圈，点击者无法确认到底提交了哪个动作。现在 loading 只出现在被点击的那个按钮上，同栏其它按钮仅置灰以防重复提交（切到另一个分片页签也不会误显示转圈）；「重置」也补上了自己的 loading，重新拉取远端配置期间转圈。

## [0.4.4] - 2026-09-15

### Fixed

- **安装摘要不再把内网地址当成「面板地址」打印**：此前主机地址取 `hostname -I` 的第一项，多网卡 / NAT 机器上常落到内网网段（云主机上即 `172.16.x.x` 这类地址），摘要却把它单行标成`面板地址`，用户会以为面板根本连不上。现在主机地址取默认路由出口（`ip route get`，回退 `hostname -I`），对外地址按「显式 `PANEL_PUBLIC_URL`/`PANEL_HOST` → 网卡公网地址 → 云平台元数据 → 出站 IP 探测 → 本机地址」解析，并在地址后标注来源；探测不到公网地址时如实标注「本机内网地址（仅同一局域网可访问）」并给出公网访问该做的事；来自出站探测的出口地址会额外提示「仅在该公网 IP 已映射到本机端口时可用」，避免 CGNAT 场景换一种方式误导。显式指定过地址的机器不发起任何探测请求，`GSH_PANEL_AUTO_PUBLIC_IP=0` 可关闭探测，`GSH_PANEL_PUBLIC_IP_BUDGET_SECONDS` 控制探测总预算（默认 3 秒）。

- **升级时不再把内网地址长期留在配置里**：`panel.env` 的 `PANEL_PUBLIC_URL` 如果是内网地址、而本次解析到了对外地址，会被纠正并写日志说明；用户自己设置的域名 / 反向代理地址一律保留。

- **Native 安装必定崩在 configuration 阶段**：`prepare_native_panel_env` 引用了只在 Docker 分支声明过的 `is_upgrade`，脚本是 `set -Eeuo pipefail`，未定义变量即致命退出——任何 `--mode native` 安装都会失败并触发回滚（v0.4.3 的 Release 附件 `install-v0.4.3.sh` 受影响）。

- **Native 单文件安装拿不到内存档位预设**：Native 分支此前不同步 `config/panel.env.presets`，`append_panel_env_preset` 只会打一条 `Preset file not found` 就跳过，小内存机器于是完全没有 DST 内存上限。现在 Native 也会先同步预设资源（本地仓库 → 内置资产 → 镜像池）。

## [0.4.3] - 2026-09-13

### Fixed

- **面板端口改完是真的会换端口了**：此前「系统设置 → 面板端口」只往数据库写一个数字，重启面板也不会改变实际端口——面板实际监听与对外的端口只由部署配置决定，所以那句「需重启面板才能生效」一直是空话。现在保存时会把新端口真正写进部署配置：Docker 部署借一键更新同款的一次性容器写入 `panel.env` 的 `PANEL_PORT`（写前备份，刻意不重建面板），Native 部署直接写 `SERVER_PORT`，下次重启面板即用上新端口；保存后界面会提醒先在安全组或防火墙放行新端口。部署目录不可达、配置文件只读等写不进去的情况，会给出可直接复制执行的命令，而不是默默失败。

- **面板端口不再被本地启动悄悄改掉，设置页也不再自相矛盾**：端口发布变量此前带了一个兜底值，会被当成「用户显式声明的对外端口」参与启动校正——在本机跑一遍生产配置，设置里的面板端口就被改写成后端监听端口（8888），于是出现「输入框写着 8888、旁边却提示当前访问端口是 9527」的画面，两个数字都"对"却指的不是同一件事。现在未显式声明就不回写数据库，已设置过的值也不会被动；设置页按部署形态说人话：服务器上显示「面板端口」，本地开发显示「前端开发服务器端口」（它真正影响的是本地前端页面端口），「当前实际端口」只在保存值与生效值不一致时出现，且改由服务端判定（兼容发布端口、反向代理与端口转发），不再读浏览器地址栏推算。**此前已经被改成 8888 的面板端口，在设置页改回 9527 保存一次即可。**

- **生产部署下实例控制台的实时日志恢复**：接口基地址在缺少配置时会被解析成非字符串，构造实时日志连接时直接抛错，日志于是静默退化成轮询、看起来像"没有日志"。现在基地址解析统一收口并有单测覆盖，构造失败时也会安排重连并明确退回轮询。

- **登录不再被陌生人的错误密码锁死**：此前登录限流把账号维度也算进封锁，攻击者用错密码打同一个账号，真正的管理员换个 IP 也会被"登录过于频繁"挡住。现在封锁只按 IP/连接维度判定，账号维度只升级为验证码；验证码答错会计入失败次数并提示「验证码不正确」，不再无限续发挑战（答案只有 19 种，等于没有节流）。

- **备份与导入/恢复互斥，存档包解压有上限**：备份此前不参与实例存档锁，导入或恢复进行中发起的备份会产出不完整的 tar 包却记为成功；现在备份纳入同一把锁，冲突时明确失败。解压新增条目数（10 万）与解压后总字节（4GB）限制，并拒绝绝对路径与 `..` 逃逸，全部在落盘前拦截；zip 与 tar.gz 两条分支的限额口径也统一了。

- **实例创建、更新、启动、停止的状态与并发修复**：安装任务没起来时不再留下没有任务的「等待安装」孤儿记录；更新失败不再永久卡在「安装中」；重复点击启动会提示「该实例正在启动中」；停止安装中的实例显示「已停止」而不是异常。

- **目录浏览不能再被符号链接带出允许范围**：允许根内的符号链接此前可以指向根外，从而浏览到不该看到的目录；现在同时校验字面路径与真实路径。

- **Native 部署的分片停机、分片删除与日志回收**：停机预算常量化并放宽客户端等待，避免存档写盘途中被判失败；删除分片先执行清理再报错，宿主重启不会再把已删除的分片拉起来；结束日志跟随时会回收 `journalctl` 进程。

- **默认开启强制改密**：`FORCE_PASSWORD_CHANGE` 的兜底值从 0 改为 1，与安装器写入的值一致。为 0 且未设置初始密码时，自动生成的初始密码会以明文长期留在 `data/admin-credentials.txt`（只有改密成功才会删除）。

- 新增「存档导入」：将外部 Klei DST 集群存档目录（支持集群目录、`DoNotStarveTogether/<用户ID>/Cluster_N` 等层级）一键导入为指定实例的世界存档。导入前自动创建「导入前」安全备份；世界数据与房间设置保留源档，端口自动重写为本实例配置并同步数据库，避免多实例端口冲突；源档 Mod 反向写入面板 Mod 列表（`pre_import` 备份类型，工作坊内容缺失时提示）；导入与恢复共用实例级互斥锁。入口在「备份与恢复」页。

- 新增「备份与恢复」：实例存档一键备份/恢复（klei-storage 全量 tar.gz）、流式下载、保留策略（默认每实例 10 份）、更新/删除实例前自动备份钩子；面板 SQLite 数据库快照（VACUUM INTO，默认保留 5 份）。恢复前自动创建安全备份，运行中实例拒绝恢复。配套新增 `ops:read`/`ops:manage` 权限点与导航「备份与恢复」页。

### Changed

- 后端默认监听端口从 `3000` 迁移至 `8888`（避免与本机常驻开发环境服务冲突，详见 `docs/DEVELOPMENT.md` 已知问题）；生产安装的对外端口仍为 `9527`（安装脚本显式写入 `SERVER_PORT`），不受影响。

- 新增 Docker / Native systemd 双运行时；Native 模式下的面板、SteamCMD 和 DST 分片均不依赖 Docker。
- Linux 安装器新增 `--mode auto|docker|native` 与 `--network auto|cn|global`，支持国内 apt 镜像、SteamCMD 重试和多源安装资源回退。
- GitHub Release 流程新增 Linux x64 Native 包与同名 SHA256 文件。
- 新增中文架构、双模式安装、升级回滚与按错误关键词排查文档。

### Changed

- 监控与 SteamCMD 页面改用通用运行时语义，不再假定 Docker。
- 同模式重跑安装器改为原地升级：保留 `panel.env`，并在升级前备份 SQLite 与部署配置。
- **破坏性**：新增 `GSH_INSTALL_PATH_POLICY`（默认 `instances-root`），创建实例的安装路径必须位于 `GSH_INSTANCES_ROOT` 之下；确需自定义目录请显式设置 `GSH_INSTALL_PATH_POLICY=any` 并自行承担隔离风险。既有实例不受影响，可继续启动与删除。
- **破坏性**：Node.js 引擎要求收敛为 `^22.13.0 || >=24`。后端使用 Node 内置 `node:sqlite`，Node 20 无法启动后端，此前文档标注的 `^20.19` 支持不成立。
- **公告补记**：0008 迁移（随 v0.1.4 发布）会把全部已启用的实例 Mod 强制禁用（`UPDATE instance_mods SET enabled = 0`），需要手动重新启用；此行为此前未在变更记录中说明。0010 迁移已把 `instance_mods.enabled` 默认值修正为 0，此后新加入的 Mod 默认禁用。

### Fixed

- 清除 Native 安装、资源快照、定时更新检查中的隐式 Docker 依赖。
- 修复已有前端类型错误，使完整 `vue-tsc` 与生产构建重新通过。
- 新增 0010 迁移补账全部影子 schema（`auth_sessions` 7 列、`game_instances` 12 列、`users.must_change_password`、维护公告两张表），并在 CI 增加 `drizzle-kit generate` 无差异门禁，防止迁移与 schema 再次漂移。
- 修复删除实例的顺序：先删数据库记录再清理磁盘目录，目录清理失败只告警，不再出现“记录仍在、文件已没”的不一致状态。
- **公告补记**：修正安装器内置 `docker-compose.yml` 校验和（`eb30aeae…` → `a34665e2…`）。旧 pin 与 tag 内文件 blob 不匹配，v0.1.4 的 Docker 安装在默认严格校验（`STRICT_INSTALLER_ASSET_CHECKSUM=1`）下会因校验失败中止；此前未被发现是因为 `install-linux-smoke.sh` 直接哈希工作区文件，Windows CRLF 检出下不会暴露真实差异。smoke 现已先归一化为 LF 再校验。
- 修复"取消安装后立即重新安装"竞态：取消不再提前清除进行中标记，取消与完成两个方向的终态写入均加前置状态守卫，任何一方都不会覆盖另一方的结果。
- SteamCMD 排队任务在获得锁时检查取消标记：排队期间被取消的任务直接跳过执行，且不再污染后续重试。
- Docker 日志 follow 流补齐销毁逻辑并接入中止信号，消费方退出时不再泄漏 docker 连接句柄。
- `updateGameInstanceRuntime` 支持 `whereStatus` 前置状态守卫，安装管线全部终态写入接入。
- 登录限流、找回/改密失败计数落 SQLite（新增 `auth_rate_limits` 表，0011 迁移），面板重启后限流状态不再清零，表容量由定期清理保证有界。
- 业务模块不再直接实例化 dockerode，统一经 infra 层 `createDockerClient` 工厂获取客户端。
- CI 质量门禁新增 release 引用一致性校验与生产构建（含服务端打包）；镜像新增 `HEALTHCHECK`（node fetch 探活 `/health`）。
- 服务端新增 esbuild 打包（`pnpm run build:server`）：Docker 镜像 production 阶段复用打包产物，`node` 直跑不再经 tsx 转译，镜像不再拷贝 server/shared 源码；运行时仓库资源（迁移目录、前端产物、DST leveldata 模板）改为从部署根统一探测定位。
- 说明：镜像暂不以非 root 用户运行——docker.sock 的宿主 gid 因发行版而异，非 root 需 entrypoint 动态调组或 compose `group_add`，且数据/日志绑定挂载需属主匹配，待部署矩阵验证后启用。
- 修复 Mod 管理在快速切换实例时旧实例响应覆盖新实例列表的竞态。
- 引入 oxlint 静态检查（`pnpm run lint:ox`，CI 以 `--deny-warnings` 门禁），清零全部告警：未用导入、多余展开拷贝、正则冗余转义等。

### Security

- Compose 安装资源使用安装器内置 SHA256，校验过程不再强制二次访问 GitHub Raw。
- Native systemd 服务采用专用无登录用户、只读 Release、受限可写路径和权限受控的控制台 FIFO。
- 登录限流不再无条件信任 `X-Forwarded-For`：仅当连接对端命中 `GSH_TRUST_PROXY` 配置的可信代理列表时才采信，并新增不可伪造的 socket 地址限流维度，阻断伪造请求头的密码喷洒。
- 自动生成的管理员初始密码不再写入日志，改为写入数据库同目录的 `admin-credentials.txt`（0600 权限），首次登录改密后自动删除。
- 前端“记住我”不再把明文密码写入 localStorage（历史遗留值会在下次访问登录页时自动清除），密码请交给浏览器密码管理器。
- 安装器写入 `panel.env` 改为 printf 逐行写入后原子落盘：环境变量传入的凭证含 `$`、反引号、引号时不再被 shell 展开破坏。
- 镜像发布流水线强制要求仓库变量 `STEAMCMD_ARCHIVE_SHA256` 非空，拒绝发布未校验的 SteamCMD 二进制。
- 安装器管理员密码回退生成改用 `/dev/urandom`（约 128 bit 熵），移除秒级时间戳弱熵回退。
- 找回密码接口新增找回口令哈希维度的失败封锁：攻击者更换 IP 也无法对同一口令持续爆破，超限后该口令在窗口内临时失效。
- CORS 反射任意 Origin（`CORS_ORIGIN=true/*`）时自动禁用凭据，消除"反射 + 凭据"组合放行任意站点携带凭据跨域调用的风险。
