# 从其他面板或裸机迁入

本文说明如何把现有的饥荒联机版（DST）存档搬到 BubbleSharkPanel，以及哪些数据能自动迁过来、哪些必须手工处理。

迁入的判据只有一个：**源目录里有饥荒的集群目录**（含 `cluster.ini`）。面板不区分你原来用的是哪个管理面板，只要存档是 Klei 的标准布局就能识别。

## 迁移前必读

- 迁入前请**先停掉源机器的游戏进程**，并自行留一份源存档副本。面板在导入前会自动创建一次备份，但那是在它自己的存储里，源文件仍应由你保管。
- 目标实例必须是**已停止**状态才能导入存档；运行中的实例会直接拒绝。
- 分片端口、玩家名单与 Mod 清单会随包带入，但**安全组与端口转发必须你手工放行**。

## 能自动完成与必须手工做的事

| 项目 | 处理方式 |
| --- | --- |
| 集群目录识别 | 自动，按 `cluster.ini` 定位，压缩包内任意包装层级都能找到 |
| 分片端口 | 自动重写，与目标实例的分片端口配置对齐 |
| 玩家名单（管理员、白名单、黑名单） | 随包带入，整目录复制 |
| 房间名 | 保留源存档 `cluster.ini` 里的值；想改成目标实例名，导入后到「世界设置」改一次 |
| Mod 清单与工坊 ID | 自动写入面板；新版迁移包可包含 Mod 文件，缺文件项恢复为待下载 |
| 集群令牌 | 按「表单填写 ＞ 实例已有 ＞ 源存档 ＞ 无」的顺序取值；都没有时只提示，不阻断导入 |
| 磁盘上的存档文件 | 自动，导入前先建安全备份，再原子替换 |
| 安全组与 NAT 端口放行 | **手工**，见[必须开放的端口](#必须开放的端口) |
| 其他面板的账号、角色与计划任务 | **不能迁移**，面板数据库只接受自己的快照 |
| Docker 模式与裸机模式之间 | **不能自动迁移**，见[常见问题](#常见问题) |

## 从其他面板或裸机迁入

共三步：取出存档、导入、放行端口。

### 1. 取出集群目录

到源机器上找到饥荒的集群目录。它一定包含一个 `cluster.ini`，常见位置有三类：

- 旧面板的存储目录；
- 本面板的实例存储目录；
- 玩家客户端目录 `DoNotStarveTogether/<userid>/Cluster_N`。

一个集群对应一个 `Cluster_1` 这样的目录。有洞穴时，目录里同时存在 `Master` 和 `Caves` 两个分片。

把该目录打包成 `.zip` 或 `.tar.gz`，包内可以有外层目录，面板会自动在其中查找集群。**打包时不要把实例安装目录（游戏本体）一起打进去**，那会让包体积失控，面板也会因为源目录包含安装目录而拒绝。

### 2. 导入存档

在面板里操作：

1. 打开「实例管理」，**先停止目标实例**。
2. 进入「备份与恢复」页，点「导入外部存档」。
3. 上传刚打好的压缩包（支持 `.zip`、`.tar.gz`、`.tgz`，上限 2 GiB）。
4. 面板会列出识别到的候选集群及各自的检查结果，选中你要导入的那个。
5. 如果源存档里没有集群令牌，在这一步填入；留空也可以，导入后到「世界设置 → 网络」补。
6. 确认导入。面板会先创建一份「导入前」备份，再执行替换。

导入完成后到「世界设置 → 网络」确认分片端口，然后启动实例。

### 3. 必须开放的端口

默认需要 6 个 UDP 端口，每个都要单独一条规则：

| 用途 | 主世界 | 洞穴 |
| --- | --- | --- |
| 游戏端口 | 10999 | 11000 |
| Steam 鉴权 | 8766 | 8768 |
| Steam 主服务器查询 | 12346 | 12348 |

外部端口必须等于内部端口。游戏会把自己配置里的端口上报给 Klei 与 Steam，平台把公网端口改成随机高位时，玩家会遇到「列表里搜得到、点不进去」。端口被平台占用时，请到「世界设置 → 网络」把该实例的分片端口改成平台分配的值。

完整说明见[必须开放的端口](install-docker.md#必须开放的端口)。

## 从裸机安装目录迁入

源机器上只有游戏本体（SteamCMD 装出来的 `DoNotStarveTogether` 目录）时，用仓库自带的导出工具生成面板可以直接导入的包：

```bash
tsx scripts/export-cluster-archive.ts --source <源目录> --out <输出目录> [--name <包名前缀>]
```

离线迁移 Mod 时，先停止源服务器，提供直接包含 `<工坊ID>/` 或 `workshop-<工坊ID>/` 的目录：

```bash
tsx scripts/export-cluster-archive.ts --source <源目录> --out <输出目录> --include-mods --mods-source <Mod目录>
```

同一 ID 只能有一份来源。启用 Mod 及必要依赖缺文件时禁止完整导出；禁用且缺文件的 Mod 只保留配置。完整包内包含版本化清单、内容校验和与报告，复制期间源内容变化会导致导出失败。未提供新参数时维持原有集群导出格式。

它只读源目录，不改动任何文件，也不会打印集群令牌与房间密码。每个集群产出三个文件：

- `<集群名>.tar.gz`：包内顶层就是集群目录（含 `cluster.ini`），拿到目标机器后用面板的「导入外部存档」直接导入；
- `<集群名>.report.txt`：分片、端口、Mod 清单与迁移前必须确认的事项；
- `<集群名>.sha256`：压缩包校验和，传输后先核对再导入。

## 从本面板迁到另一台机器

如果源机器已经在用 BubbleSharkPanel，改用实例详情页的「迁移到其他机器」卡片：点「检查迁移报告」先看风险项，确认无误后点「导出迁移包」。

勾选「包含 Mod 文件」可离线迁移，实际导出前必须停止实例。默认只迁移世界与完整 Mod 配置列表；两种模式均包含版本化清单和报告。浏览器下载压缩包，校验和与报告的附属文件保留在服务端。需要 `instance.migration:export` 权限，产物只保留 24 小时，不进入备份列表。

## 导入后的检查清单

1. 启动实例，进入「控制台」确认日志里没有端口冲突或 Mod 加载失败。
2. 到「玩家管理」核对管理员、白名单和黑名单。
3. 到「模组管理」核对 Mod；新版完整迁移包可直接离线恢复，缺文件项通过现有下载队列手动补齐。也可用「从本地导入」上传包含一个或多个 Mod 的 ZIP、确认 Workshop ID 后安装；每个 Mod 目录须包含 modinfo.lua，目录名为 Workshop ID 或 workshop-ID 时可自动识别。新增项默认禁用，覆盖保留启用状态、顺序和配置；失败项恢复原状，成功项保留，可在预览有效期一小时内重试未完成项。上传预览可在线进行，确认安装必须停服。
4. 到「备份与恢复」确认导入时创建的那份「导入前」备份存在。
5. 让一名玩家实际进一次服，主世界与洞穴各试一次。

## 常见问题

**导入时提示「这不是有效的存档目录（缺少房间配置文件）」？** 上传的压缩包里没有 `cluster.ini`，检查打包的是不是集群目录本身，而不是它的上一层。

**导入时提示「实例运行中，必须先停止实例再导入存档」？** 到「实例管理」停止该实例后重试。

**导入后玩家进不去？** 先查安全组的 6 个 UDP 端口是否逐条放行，再查外部端口与内部端口是否一致。

**Mod 要重新订阅吗？** 清单会随包带入。新版完整迁移包会恢复包内文件，并校验每个 Mod 的内容摘要；配置包和旧包缺失的文件需手动下载或从本地 ZIP 导入。新版包恢复不自动联网下载，即使开启自动下载环境变量也不会在恢复过程中启动队列。本地导入内容的 Workshop 更新时间显示为未知，显式重新下载后恢复 Steam 版本凭据。

**旧面板的账号和计划任务能一起迁过来吗？** 不能。面板数据库只接受本面板自己的快照，账号、角色与计划任务需要在新面板里重建。

**能在 Docker 模式和裸机模式之间迁移吗？** 两种模式之间不自动迁移。保留数据目录后按目标模式重装，再手工迁移数据。

**迁移会不会影响源机器上的存档？** 不会。导出工具与面板导出都只读源存档，不改动源文件。
